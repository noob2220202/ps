## 2. 방법

하나 답지 spec/font.md 의 방법(영상과 같은 배율로 크게 렌더 → 축소, 잉크 맞춤 fitError)을 따르고, 우리 영상의 단위(units.json)에 맞췄다.

1. **표본**: 두 영상·7개 화면의 정지 구간 중앙값(clean 영상, `tools/ref/font/*.png`)에서 글자 24개를 골랐다. 한글 굵은 제목, 본문, 숫자(잔액·날짜·시각·키패드), 영문(WON, SC), 기호(`?` `!` `,` `.` `~` `-` `·` `:`), 흰 글자/파란 바탕, 연파랑 바탕.
   이름·계좌번호가 든 글자는 고르지 않았다(개인정보).
2. **폰 경로 렌더(video)**: Playwright Chromium 으로 후보 글꼴을 **DSF 3(= 폰 1080 기기px)** 로 그린 뒤, 녹화와 같은 배율 — 가로 1.45803, 세로 16/11 px/dp(가로 0.24% 비등방) — 로 **면적 평균 축소**했다.
   글자 위치는 가로 1/4 기기px, 세로 1 기기px 격자에서 찾는다(Chromium 글자 배치 규칙, README 5절).
3. **탐색**: 후보마다 굵기(가변 글꼴 300–800 을 100 단위, 정적 글꼴은 있는 굵기) × 크기(0.25dp) × 자간(0.01em → 0.0025em) × 위치.
4. **fitError** = Σ|Y영상 − Y렌더| / Σ|Y영상 − Y배경| (잉크 상자 + 4px, 휘도만). 글자색·배경색은 영상의 코어·바깥 고리 값.
5. 숫자는 proportional / tabular 둘 다 본다(`--numeric both`).

후보 글꼴(모두 npm 에서 받음): Pretendard Variable 1.3.9, SUIT Variable 2.0.5(@sun-typeface/suit), Noto Sans KR Variable(@fontsource-variable/noto-sans-kr 5.3.1),
Spoqa Han Sans Neo(spoqa-han-sans 3.3.0), Wanted Sans Variable 1.0.3, 나눔스퀘어 네오 Variable(nanumsquareneo 0.0.5), IBM Plex Sans KR(@fontsource 5.3.0),
나눔고딕(@fontsource 5.3.0), G마켓 산스 Medium(@noonnu/gmarket-sans-medium, 다른 굵기는 npm 에 없음), **우리다움체 B**(@noonnu/wooridaum-b — 우리은행 전용서체, npm 에는 Bold 하나뿐),
Roboto + Noto Sans KR(안드로이드 기본 `sans-serif` 조합의 근사).
삼성 One UI 시스템 글꼴(SamsungOne / One UI Sans 한글)은 배포 라이선스가 없는 독점 글꼴이라 받지 않았다(7절).

## 5. 숫자 정렬 (tabular-nums)

- 거래내역(잔액·금액·날짜·시각), 홈 잔액, 키패드, 이체 화면 날짜는 **proportional** 이다. 예: '2026.11.21' proportional 0.142 / tabular 0.643, '11:02:40' 0.151 / 0.489, '2026.08.21 ~ …' proportional 0.159 (tabular 0.47).
- **거래 상세의 값 열(거래일시 '2026.11.20 21:29:47' 등)은 tabular** 이다: 날짜 '2026.11.20' proportional 0.66(500)–1.11(400) / tabular 0.113, 시각 '21:29:47' proportional 0.45 / tabular 0.118. 이 열의 다른 숫자(거래 후 잔액·수표금액)도 같은 컴포넌트일 가능성이 높다 — history-detail 스펙에서 `--numeric both` 로 확인.
- 그래서 전역 기본은 `font-variant-numeric: normal` 이고, 상세 값 열에만 `tabular-nums` 를 준다(하나 답지는 전역 tabular 였다 — 우리는 다르다).

## 6. 자간 · 줄 높이 · 기준선

- **자간 0**: 22개 표본의 설계값이 모두 0 ± 0.0125em(키패드 한 글자는 자간이 의미 없음). 거래 상세 값(tabular)만 −0.025em 근처로 나왔다(크기 14.75dp 와 함께 — 15dp·−0.03em 일 수도 있다).
  `letter-spacing` 은 전역 0(브라우저 기본). 자간을 주지 않는다.
- 줄 높이: 영상만으로는 line-height 를 알 수 없다(한 줄 글자). 맞춤 도구는 `line-height: 1` 상자로 위치를 낸다. 두 줄 글자('오늘 같은 내용으로 보냈어요! / 한 번 더 보낼까요?')는 두 줄의 기준선 간격을 재서 화면 스펙에서 정한다.
- 기준선: Chromium 은 글자 기준선을 **기기 px 정수 행**에 붙인다(DSF 16/11 에서 1행 = 0.6875dp). top·translateY 의 소수는 반올림된다. 가로 글자 위치는 1/4 기기 px 단위. 자세한 규칙과 도구의 `place` 출력은 tools/README-textfit.md 5절.
- Pretendard 메트릭: ascent 0.952em, descent 0.241em(하나 답지 측정과 같은 파일). line-height:1 상자 위끝 → 기준선은 도구가 `baselineOffsetDp` 로 낸다(실측: 13→11, 14→12, 15→12, 16→13, 17→14, 20→17, 22→19, 25→21 dp).

## 7. 시스템 글꼴 가능성과 라이선스

- 원래 앱이 삼성 시스템 글꼴(One UI Sans / SamsungOne 한글)을 쓸 가능성: Pretendard 의 오차가 영상 노이즈 수준(큰 글자 0.05–0.08, 두 영상 사이 차이 0.01)이고 숫자 `1`·`4`·`7`, `?` 모양까지 맞으므로 **앱은 Pretendard 를 웹 폰트로 싣는다**고 본다. 삼성 글꼴은 독점 라이선스라 받지 않았고 비교하지 않았다.
  만약 일부 화면(예: 앱 밖 OS 화면, 삼성 키보드 D5)이 시스템 글꼴이면 그 부분은 그 화면 스펙이 따로 맞춘다 — 그때도 저장소에는 공개 글꼴만 넣는다.
- 저장소에 넣은 글꼴은 Pretendard 하나(OFL 1.1). OFL 은 수정 없이 번들·재배포를 허락하고, 라이선스 문구를 함께 둘 것을 요구한다 → `frontend/public/fonts/LICENSE-Pretendard.txt`. 이름을 바꾸거나 글자를 빼서(서브셋) "Pretendard" 이름으로 내보내면 Reserved Font Name 조항에 걸리므로 **원본 파일 그대로** 둔다.
- 비교에만 쓴 후보 글꼴 파일은 스크래치에만 있고 저장소에 넣지 않았다.

## 8. 웹 폰트 로드

```html
<!-- frontend/index.html (프론트 뼈대 작업이 넣는다) -->
<link rel="preload" href="/fonts/PretendardVariable.woff2" as="font" type="font/woff2" crossorigin>
<link rel="stylesheet" href="/fonts/woori-font.css">
```

```css
/* frontend/public/fonts/woori-font.css (이미 있음) */
@font-face {
  font-family: 'Pretendard Variable';
  font-style: normal;
  font-weight: 45 920;
  font-display: block;
  src: url('./PretendardVariable.woff2') format('woff2-variations'), url('./PretendardVariable.woff2') format('woff2');
}
/* 전역 (woori-*.css) */
:root { --woori-font: 'Pretendard Variable', Pretendard, -apple-system, BlinkMacSystemFont, system-ui, Roboto, 'Helvetica Neue', 'Segoe UI', 'Apple SD Gothic Neo', 'Noto Sans KR', 'Malgun Gothic', sans-serif; }
html, body { font-family: var(--woori-font); letter-spacing: 0; font-variant-numeric: normal; -webkit-font-smoothing: antialiased; }
```

- **`font-display: block`**: 글꼴이 오기 전 대체 글꼴로 그렸다 바뀌는 깜빡임을 막는다(답지는 로컬 서버라 지연이 짧다). 스크린샷 준비 신호(`window.__WOORI_READY__`)는 `await document.fonts.ready` 와
  `await document.fonts.load('600 17px "Pretendard Variable"', '가1')` 뒤에 켠다.
- **서브셋 안 함**: 파일 하나(2.06MB, woff2)에 한글 11,172자 전부. 더미 이름·직접 입력 글자가 어떤 한글이든 나오게 하고, 앱과 맞춤 도구가 **같은 파일**로 그리게 하려는 것이다.
  (KS X 1001 2,350자 서브셋은 '똠' 같은 글자가 빠지고, Pretendard 의 92조각 동적 서브셋은 unicode-range 로 나눠 받아 처음 그릴 때 조각 도착 순서에 따라 깜빡일 수 있다.) 크기가 문제가 되면 npm 의 `pretendardvariable-dynamic-subset.css` 로 바꿀 수 있다 — 글자 모양은 같다.
- 런타임 CDN 은 쓰지 않는다(자체 호스팅, `/fonts/`). 프론트 빌드(Vite)는 `public/` 을 그대로 복사한다.
- 맞춤 도구는 같은 `woori-font.css` 를 `file://` 로 불러 렌더한다 — CSS 를 바꾸면 도구 결과도 같이 바뀐다.

## 10. 독립 재검증 (critic-font, 2026-11-21)

위 24개와 **겹치지 않는 화면** 6곳에서 다시 쟀다(clean 영상 중앙값, 잉크 상자는 따로 잰 값). video 경로, 각 글꼴의 최적 굵기·크기·자간.

| 표본 (화면, 기준 프레임) | Pretendard | Wanted Sans | SUIT | Roboto+Noto |
|---|---|---|---|---|

- Pretendard 가 6개 중 5개 1등. 한글만 있는 '추천서비스' 는 Wanted Sans 와 0.002 차(같은 값) — 3절의 "한글은 Wanted 와 거의 같고 숫자에서 갈린다"와 같다. 숫자가 든 4개에서는 2등과 0.06–0.10 차.
- 거래 상세 값 열 tabular 는 **다른 상세 화면(출금)에서도** 같은 값(14.75/−0.025em)으로 나왔다(5절 확인).
- 새 표본 6개(두 영상, 14–25dp, 500/600/700)에 도구를 돌려 `place.css` 를 **앱과 같은 구조의 독립 페이지**(8절 전역 CSS, `/fonts/woori-font.css` 를 http 로 로드, 위 31dp + 셸 transform)에 그대로 그려 기준과 겹쳤다:
  최적 소수 px 이동량(L1 최소)이 가로 0.00–0.05px, 세로 0.00–0.45px — 모두 0.5px 안. 셸 안 오차는 도구의 `place.fitError` 와 ±0.002 로 같다. 세로 0.45px 는 기준선이 기기 px 정수 행에 붙는 렌더러 한계(5절)다.
- 금액 입력의 큰 '2원'(send-amount, v2 #2956–#2957)은 한 문자열로는 600/25.25/+0.045em tabular 로만 맞는다 — 숫자와 '원' 사이가 벌어져 있다. '원' 하나는 600/25 (0.067). 숫자와 단위가 따로 놓인 요소일 가능성이 높으니 send-b 스펙에서 덩어리로 나눠 잰다(README-textfit 6절 함정 1).
