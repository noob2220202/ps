# launch — 스플래시 · 우리WON인증서 PIN · 로그인 로딩 (스펙)

원본: `v1-clean.mp4` **1.748–10.061 s** (#52–#274). 이 그룹 화면은 v1 에만 있다(v2 는 거래내역에서 시작).
인증서 PIN 키패드 설계 근거로 계좌 비밀번호 시트 누출 프레임(v1 188.273–188.674 #7191–#7208, v2 80.453–80.852 #3002–#3021)을 함께 쟀다.
기계용: [`launch.json`](launch.json) (상태·요소·전환·컷·동작), 에셋 표 [`launch.assets.json`](launch.assets.json) (6절), 생성물 [`dp/launch.json`](dp/launch.json). 덧붙인 shot 항목: `tools/shots.d/launch.json`.

> 개인정보: 이 그룹 화면에는 사람 이름·계좌번호가 없다. 누출 프레임 첫 장(#7191)에는 **누른 키 강조**가 보이는데, 섞인 배치와 함께 보면 비밀번호 자릿값이 되므로 어느 키였는지는 어디에도 적지 않는다(모양·색·크기만).
> 누출 프레임 뒤쪽 딤 아래에는 이체 화면(실명·계좌)이 비친다 — 그 프레임으로 만든 기준·크롭·비교 그림은 `tools/ref/launch/`(git 제외)와 스크래치에만 있다.

## 0. 읽는 법

- **좌표**: `box` = frame px (524x1280, 화면 절대). 가장자리는 휘도(Y)의 50% 지점을 소수 px 로(원·알약은 원 맞춤, 1dp 선은 잉크 중심 ± 0.5dp). 글자 `box` 는 잉크 상자.
- **dp**: 설계 dp, **y 는 앱 뷰포트 기준**(화면 dp − 31.333). 가로는 D1 식 `x_dp = 180 + (x_px − 262.02)/1.45803`, 세로 `y_dp = y_px × 0.6875 − 31.333`. `spec-to-dp` 검사: 304개 설계 dp, D1 과 최대 차이 0.21dp.
- **글자**: `tools/woori-textfit.cjs` 의 `best`(= 폰 경로 설계 크기·굵기·자간 + DSF 16/11 shot 위치). json 요소의 `css` 가 그대로 쓸 CSS(`position:absolute; line-height:1; left; top`, 앱 좌표), `font.fitError` 는 design 오차, `font.keep.shotFitError` 는 shot 렌더 오차.
  글자 크기(`sizeDp`)·지연(`latencyMs`)처럼 spec-to-dp 키 표에 없는 숫자는 `keep{}` 아래에 있다.
- **시각**: 영상 초(3자리)와 원본 프레임 `#n`(VFR — "시각 t 의 화면" = pts ≤ t 마지막 프레임). 전환의 ms 는 trigger 프레임 pts 기준.
- **설계값**: 영상에 없는 것은 json 에 `"design": true`, 이 문서에 **설계값(영상에 없음)**. 설계 상태는 `states` 가 아니라 `designStates` 에 있다(기준 프레임·비교 없음).
- 기준 프레임: `tools/ref/launch/<id>.png` = `python3 tools/woori_video.py ref --video v1 --i0 '#a' --i1 '#b'` (clean 영상 중앙값). 6개 모두 왼쪽 손잡이 자리(x 0–7, y 149–320) 평균 254 ± 1(열별 최대 −3 레벨, woori_edge 잔여). 단 스플래시 프레임(#52–#91)에서만 손잡이 아래 끝 y 318–319, x 0–5 에 1–11화소, 최대 28 레벨의 잔여 점이 남는다(clean 영상 자체 — 인증서·로그인 로딩 프레임에는 없음). 비교에서는 >24 화소 몇 개(splash-logo-end 1개, f60 최대 7개)라 점수에 거의 안 걸린다(critic, 남은 일: woori_edge).

- 크기가 정수 dp 가 아닌 것(트랙 75.15x40.88, 원 50.6)은 로고가 그림 배율로 그려졌기 때문으로 본다 — 잰 값을 그대로 쓴다. 원 지름은 가로 50.55 / 세로 50.67dp(가로 0.24% 비등방이 원에서도 보임) → CSS 는 50.6dp 원.
- 원은 트랙보다 위아래로 4.9dp 씩 크다(원 357.79–408.46, 트랙 362.68–403.56). 시작에 원 왼끝 142.51 ≈ 트랙 왼끝 142.35, 끝에 원 오른끝 217.48 ≈ 트랙 오른끝 217.50 — **트랙 왼끝 정렬 → 오른끝 정렬로 24.42dp 이동**.
- **그라데이션은 트랙에 붙어 있다**: 같은 x 의 색이 드러난 뒤로 프레임마다 같다(#57–#71, 예: x 211 = (56,204,246) 계속). 즉 채움 상자는 넓어지지만 색이 늘어나지 않는다 → 구현: 트랙 폭(75.15dp) 고정 그라데이션을 `overflow:hidden` 상자(왼끝 고정, 폭 25.44→49.85dp) 안에 두거나 `clip-path: inset(0 <트랙 오른끝 − 원 중심> 0 0 round 20.44dp)`.
  보이는 범위에서 직선: 처음(스펙 단계) x 207.1–243.0px 두 끝 값 `#31c8f2`→`#98eefb` 로 적었고, **에셋 단계에서 다시 쟀다**: 끝 프레임 x 211–240(왼 반원 가장자리 빼고)·행 592–613 채널별 직선 최소제곱 R 43.06+4.543·x, G 199.61+1.547·x, B 243.69+0.270·x (x = 트랙 왼끝에서 dp, rms 1.5/1.0/1.6 — 4:2:0 색차 잡음) → 0dp `#2bc8f4`, 24.6dp `#9beefa`. 끝 상태에서도 원 위아래 모서리 틈(트랙 위·아래 가장자리 근처)에는 ≈35dp 까지 보이므로 그 너머도 같은 직선을 쓰고 255 에서 자른다(G 35.80·B 41.88·R 46.65dp 에서 255 — 정지점 `#cefffd`·`#e9ffff`·`#ffffff`). shot 비교(끝 채움 영역 평균차)는 새 값 3.32, 처음 값 3.51. 세로로는 같은 색(열 225: 위에서 아래까지 (99–102, 217–219, 249–251)).
- 채움 높이: 영상 Y 평면(코덱 색 번짐·RGB 클리핑 없음)에 모양 맞춤하면 채움은 위 362.675·높이 **41.0dp**(트랙 362.74·40.81)로 트랙보다 0.12dp 크다 — 채움 아래 가장자리가 트랙보다 아래로 조금 나온다. 에셋은 41.0dp.
- 시작 상태에서 채움(폭 25.44dp)은 원 뒤에 다 가려져 보이지 않는다. 회색 트랙은 원 오른쪽(x 281–316.7px)만 보인다.

  - 뒤 육각형: 오른쪽으로 ≈280px/s(**192dp/s**) 흐르고 112dp 상자 양 끝에서 잘림(오른쪽 것이 9.634 에 나가고 9.668 에 왼쪽에서 새 것이 들어옴). 날개도 펄럭인다.
  - 그림 갱신은 **24fps 단위**(바뀌는 프레임 간격 33/50ms 번갈아, 평균 45ms) — 대체 그림은 매끈하게 움직여도 된다(마스크 안).
  - 대체 그림은 상자 `overflow:hidden`, 몸통 `translateY` ±3dp 880ms ease-in-out 반복, 뒤 도형 `translateX` 192dp/s 반복. 시작 위상: 몸통이 위(가장 높은 쪽)에서 내려가기 시작.
  - 에셋(6절): 세 겹 SVG 를 화면 CSS 로 움직인다 — 육각형 띠(112dp 무늬 `repeat-x`, `translateX 0→112dp` 583.333ms linear 반복 = 192dp/s), 몸통+날개 묶음(`translateY −3.09→+3.09→−3.09dp` 880ms ease-in-out, `animation-delay −124ms` → 가장 낮은 때 +316ms = 실측), 날개(`scaleY 1→0.6` 240ms 왕복, 뿌리 54.46% 36.61% — 날개 리듬은 설계값). 키프레임 전문은 `spec/launch.assets.json` 의 css 설명.
