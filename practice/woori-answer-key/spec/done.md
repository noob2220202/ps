## 0. 읽는 법

- **좌표**: `box`/`inkBox` = frame px (524×1280, 화면 절대, 상태바 포함). `dp` = 설계 dp, y 는 **앱 뷰포트 기준**(CSS top = 화면 dp − 31.333). 변환 D1: `x_dp = 180 + (x_px − 262.02)/1.45803`, `y_dp = y_px × 0.6875 − 31.333`, 폭 `/1.45803`, 높이 `×0.6875`. spec-to-dp 가 frame→D1 과 설계 dp 를 비교한다(340개, 0.5dp 넘는 것은 저대비 카드 가장자리 3개 — `dpLoose` + 이유).
- **기준 프레임**: `tools/ref/done/<state>.png` (clean 영상 중앙값, `python3 tools/woori_video.py ref --video vN --i0 '#a' --i1 '#b'`). 두 영상에 다 나온 상태는 다른 영상 판을 `<state>-v2.png`(또는 `-v1`)로 만들어 json `keep.alt` 와 shots.d 에 넣었다. 체크 애니메이션 위상 기준은 `tools/ref/done/anim-*.png`(한 프레임).
- **측정**: 상자 = 휘도 50% 가장자리(연속 좌표, 둥근 모서리 피해 변 가운데), 모서리 반지름 = 위끝 아래 행 경계를 원에 맞춤, 원 = 180 방향 50% 가장자리 최소제곱(가로·세로 지름 따로), 1dp 선 = 잉크 합을 1dp 로 환산, 체크 획 = 둥근 끝 굵은 꺾인 선(4×4 초표본, 번짐 σ 0.45px)을 휘도 알파에 최소제곱. 이 화면의 카드(#f6f7fa)는 흰 바탕과 8레벨 차라 가장자리가 ±0.3px 흔들린다.
- **글자**: `tools/woori-textfit.cjs` 의 `best`(= 폰 경로 설계 크기·굵기·자간 + DSF 16/11 셸 위치, D10). 표의 `L/T` 는 `position:absolute; line-height:1` 상자의 left/top(앱 dp), `+0.25px` 는 `transform: translateY(0.25px)`. 오차 = design(fitError, 폰 경로) / shot(스크린샷 경로). 이름·계좌는 영상 글자로 맞추고(결과는 스크래치에만) 스펙에는 더미를 쓴다. 오른쪽 정렬 값은 **오른끝을 고정**하고 더미 글자 폭으로 left 를 다시 계산했다.
- **시간**: VFR — 시각 t 의 화면 = pts ≤ t 인 마지막 프레임. 곡선은 프레임 pts 그대로, 시각 흔들림 허용 없이 맞췄다(D8). 두 영상에 같은 움직임이 있으면 곡선·길이 공통, 시작만 영상마다(체크 원·획, 버튼 누름). rms 단위는 frame px.
- **더미**: 받는 분 정우진 · 지역농축협 12345652789012 · 카카오뱅크 3333123456789 (privacy.json). 이름은 한글이라 실명과 폭이 같고(22/600 119.33dp), 번호는 더미가 좁다(지역농축협 번호 122.75 vs 130.42dp). 그 자리는 json `privacyMask` 로 적고 shots.d `maskAdd` 에 넣었다: 제목 이름 `172,322,100,38`, 번호 줄 v1 `232,524,198,26` / S1 `232,492,198,26` / v2 `250,490,180,30`.

### 6.1 체크 원 SVG (`done.check-circle`) — 애니메이션 가능한 구조

```
<svg width=60 height=60 viewBox="0 0 60 60" overflow="visible">
  <g class="woori-done-check__badge" style="transform-origin:30px 30px">      ← 원 scale(3.2) 을 여기(원+체크 같이)
    <circle class="woori-done-check__disc" cx=30 cy=30 r=30 fill=#2286f2/>
    <path class="woori-done-check__mark" d="M18.27 28.56L27.05 37.47L41.701 22.625" pathLength="33.366"
          stroke=#fff stroke-width=6 round/round stroke-dasharray="32.938 100"/>   ← 획(3.3)은 stroke-dasharray
```
- 정지 모습은 파일 그대로(<img> 로 놓아도 같다). 경로는 긴 획을 끝 너머 0.428dp(P2+)까지 늘여 넘침 1.013(33.37dp)을 그릴 수 있고, 정지 dasharray 가 P2 까지만 보이게 한다. pathLength = 실제 길이라 3.3 의 dash 값(dp)을 그대로 쓴다.
- 애니메이션은 이 마크업을 **인라인**(JSX)으로 옮겨 건다(<img> 안의 획은 움직일 수 없다). 뿌리 `overflow="visible"` 이 없으면 1.05 로 키울 때 60×60 밖이 잘린다(peak 위상 지름 90.58 → 91.36px, 원 자리 평균차 2.72 → 1.80).
- **원 scale 은 `__badge`(원+체크)에 건다**: 체크 첫 점 위상(anim-check-dot, 원 0.969)에서 체크 무게중심 어긋남이 원만 키우면 (−0.73, −0.11)px, 같이 키우면 (−0.25, −0.01)px.
- **획 보이기 시작 = 원 +210ms 권장**(획 시작 +16ms): 길이 0 근처 dash 도 둥근 끝 6dp 점으로 그려지는데 영상은 획 시작 +3/+5ms 프레임(v2 #3305 · v1 #7447)에 점이 없고 +27ms 에 처음 보인다. 194 로 두면 anim-circle-low(t 197.1)에 없는 점이 생긴다(평균차 2.03 → 1.55).
- 검증: idle v1/v2 원 자리 평균차 2.358/2.216, 체크 알파 L1 0.0056/0.0058(무게중심 0.02px), 원 띠 L1 0.011/0.010. 위상 8개(shots.d anim-*) 평균차 1.21–2.07. Chromium 은 60dp 원을 50% 가장자리 지름 87.16px 로 그려 영상(87.62×87.39)보다 0.35px 작다 — div border-radius 원도 87.19 라 래스터 차이로 보고 설계 60 을 둔다(r 30.1 이면 맞고 평균차 2.358 → 2.322). 굵기 5.85/5.9/6 중 6 이 가장 맞다.
