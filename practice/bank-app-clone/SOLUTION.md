## 1. 스플래시 — 단계(phase) 상태 하나로 애니메이션 전체를 지휘

`Splash.tsx`는 `phase: "launch" | "logo" | "brand"` 상태 하나만 갖고, 타이머로 단계를 넘깁니다.
실제 움직임은 전부 CSS가 `.splash--logo`, `.splash--brand` 클래스에 반응해서 처리합니다.

- **앱 실행 애니메이션**: `clip-path: inset(... round 48px)` → `inset(0 round 0)`.
  작은 둥근 사각형이 화면 전체로 펼쳐지는 효과를 요소 크기 변경 없이(리플로우 없이) 냄.
- **B가 작아지며 워드마크가 펼쳐짐**: B는 `transform: scale(2.2) → scale(1)`,
  워드마크는 `max-width: 0 → 200px`. 부모가 `justify-content: center`라서 워드마크 폭이
  늘어나면 **B가 자동으로 왼쪽으로 밀려남** — B 위치를 따로 계산할 필요가 없음.
- **흔한 버그**: `App`에서 `onDone={() => setBoot("loading")}`처럼 화살표 함수를 바로 넘기면
  App이 리렌더될 때마다 새 함수 → Splash의 `useEffect([onDone])`가 다시 돌아서 **타이머가 리셋**됨.
  그래서 `useCallback`으로 고정. (effect 의존성에 함수가 들어가면 항상 의심할 것)

## 2. 홈 — "두 번에 나눠 그리기"와 끼어드는 애니메이션

### 2단계 렌더
첫 진입 때만 `wave 1 → wave 2`. 모듈 변수 `booted`로 "이미 한 번 켜졌는지"를 기억해서
상세에서 뒤로 왔을 땐 처음부터 wave 2로 그림. (state는 언마운트되면 사라지므로 모듈 변수)

### 높이가 0에서 자연스럽게 펼쳐지는 애니메이션 (`Collapse`)
`height: auto`는 transition이 안 됩니다. 대신:

```css
.collapsible { display: grid; grid-template-rows: 1fr; transition: grid-template-rows 320ms; }
.collapsible--closed { grid-template-rows: 0fr; }
.collapsible > * { overflow: hidden; min-height: 0; }
```

`0fr ↔ 1fr`은 애니메이션이 됩니다. 광고 등장, 광고 닫기(X), AI 목표적금 닫기, 카드 섹션 등장에 전부 재사용.
예전 방식인 `max-height: 500px` 트릭은 실제 높이와 차이만큼 타이밍이 어긋나서 덜 자연스러움.

### AI pill — 방문할 때마다 다음 문구
- **틀리기 쉬운 지점 ①**: 렌더 중에 `visits++` → 개발 모드 StrictMode는 컴포넌트를 **두 번 렌더**하므로 2씩 증가.
- **틀리기 쉬운 지점 ②**: `location.key`로 방문을 구분 → 뒤로가기는 **같은 히스토리 항목**으로 돌아가서 key가 똑같음.
  (실제로 이 버그가 났었음: 재방문해도 문구가 안 바뀜)
- **정답**: effect 안에서 증가 + `useRef` 가드. StrictMode는 effect를 "마운트→정리→마운트"로 두 번 돌리지만
  ref 값은 그 사이에 유지되므로 `if (counted.current) return`으로 한 번만 셈.
- 재방문 연출: `previous`(이전 문구) → `spinner` → `typing` 3단계 상태.

### 타이핑 효과 (`useTypewriter`)
`setInterval`로 보여줄 글자 수를 1씩 늘림. 문자열을 `Array.from(text)`로 쪼개는 이유:
`text.slice()`는 UTF-16 단위라 이모지 같은 문자가 반으로 잘림. (한글 완성형은 괜찮지만 습관으로)
`\n`이 포함된 문구는 CSS `white-space: pre-line`으로 줄바꿈.

### 이벤트 버블링
계좌 행 전체가 클릭 영역인데 안에 `이체` 버튼이 있음 → 버튼 `onClick`에서 `e.stopPropagation()`.
안 하면 이체 버튼을 눌러도 상세 페이지로 넘어감.

### 탭하면 스피너 → 이동
`setPressing(id)` 후 `setTimeout(navigate, 300)`. 사용자에게 "눌렸다"는 피드백을 먼저 주고 이동.

## 3. 로딩 UI — 서버 지연 + 스켈레톤

백엔드는 GET 응답을 일부러 `API_DELAY_MS`(기본 250ms)만큼 늦게 보냄. 화면은 "데이터는 늦게 온다"는
전제로 짜야 하고, 그래야 스켈레톤/스피너를 연습할 수 있음.

`useAsync`의 `cancelled` 플래그: 응답이 오기 전에 화면을 떠나면(뒤로가기 연타) 언마운트된
컴포넌트에 `setState` 하지 않도록. 요청 A가 늦게 오고 요청 B가 먼저 오는 **레이스 컨디션**도 같은 원리로 막힘.

스켈레톤의 반짝임: `linear-gradient` 배경을 `background-size: 200%`로 키우고 `background-position`을 이동.

## 4. 계좌 상세 — 스크롤 연동 효과

- `useScrollTop`이 스크롤 위치를 state로 줌. `requestAnimationFrame`으로 묶어서
  스크롤 이벤트(초당 수십~수백 번)마다 리렌더되는 걸 프레임당 1번으로 제한.
- 일러스트: `opacity = 1 - scrollTop / 160`, `translateY(scrollTop * 0.35)` → 스크롤보다 느리게 움직여 패럴랙스.
- **실제로 났던 버그**: 처음엔 `useScrollTop(ref)` + `useEffect(..., [ref])`로 짰는데, 로딩 중엔
  스켈레톤이 렌더돼서 `ref.current`가 null → 본문이 나중에 생겨도 ref 객체는 같아서 effect가 다시 안 돎
  → 스크롤 리스너가 영영 안 붙음. 해결: `useState`를 **콜백 ref**로 써서 요소 자체를 의존성으로.
  ```tsx
  const [el, setEl] = useState<HTMLDivElement | null>(null);
  const top = useScrollTop(el);
  return <div ref={setEl}>...
  ```
- 헤더는 `position: sticky`. 스크롤 40px 넘으면 배경색을 깔아서 내용이 비치지 않게.

## 5. 전체 내역 — 맨 위로 버튼, 누름 하이라이트

- `맨 위로`: `scrollTop > 320`일 때 클래스 토글 → `opacity`/`translateY` transition.
  `pointer-events: none`을 같이 줘야 안 보일 때 클릭이 안 먹힘. 누르면 `scrollTo({ top: 0, behavior: "smooth" })`.
- 행을 누르면 `activeId`로 160ms 회색 유지 후 이동. `:active`만 쓰면 손을 떼는 순간 사라져서
  영상처럼 "눌린 채로 넘어가는" 느낌이 안 남.

## 6. 거래 상세 — 미리 아는 데이터는 먼저 그리기

목록에서 이동할 때 `navigate(url, { state: { tx } })`로 요약 데이터를 같이 넘김.
상세 화면은 그걸로 **태그/제목을 즉시** 그리고, 나머지만 스피너 → 영상과 동일한 순서.
새로고침하면 state가 없으니 API 응답으로 그림(둘 다 대응).

행 목록은 `groups()` 함수가 배열로 만들고 `.filter(row => row.value)`로 없는 항목(주소 등)을 뺌 →
JSX에 `{d.address && ...}`를 반복하지 않아도 됨.

## 7. 데이터 — 저장하지 말고 계산하기

서버(`server/index.mjs`)는 "거래 후 잔액"을 저장하지 않고 현재 잔액에서 거꾸로 빼가며 계산.
잔액을 데이터마다 손으로 적으면 하나만 틀려도 전체가 어긋남. 계산 가능한 값은 계산.

## 8. 상태바 색 바꾸기 — Context

화면마다 상태바 색이 다름(홈=검정, 상세=라벤더, 이체=흰색). 각 화면이 `useStatusBar(bg, fg)`를
호출하면 Context를 통해 `PhoneFrame`의 상태바가 바뀜. 화면이 상태바 컴포넌트를 직접 알 필요가 없는 구조.

## 체크리스트

- [ ] effect 의존성에 함수가 있으면 `useCallback`으로 고정했는가
- [ ] `setTimeout`/`setInterval`/이벤트 리스너는 cleanup에서 해제했는가
- [ ] StrictMode에서 두 번 실행돼도 결과가 같은가 (카운터, API 호출)
- [ ] 나중에 생기는 DOM 요소에 리스너를 붙일 때 콜백 ref를 썼는가
- [ ] `height: auto` 애니메이션이 필요하면 grid `0fr ↔ 1fr`
- [ ] 클릭 영역 안의 버튼은 `stopPropagation`
- [ ] 비동기 응답이 언마운트 후에 와도 안전한가

## 9. 아이폰 버전 — 플랫폼 분기

### 분기를 한 곳에 모으기
`platform/platform.ts`가 OS를 한 번 정하고 `<html data-os="ios">`를 붙입니다.
- **CSS 차이**는 `[data-os="ios"] .bottom-nav { ... }`처럼 CSS에서 처리 → 컴포넌트 코드에 `if`가 안 늘어남
- **생김새 자체가 다른 것**(스피너, 뒤로 아이콘)만 `Spinner`, `BackButton` 같은 작은 컴포넌트 안에서 분기
- 화면 코드(`HomeScreen` 등)는 OS를 거의 모름 → 나중에 OS가 하나 더 생겨도 화면은 안 고침

`main.tsx`에서 platform을 **제일 먼저** import하는 이유: CSS가 적용되기 전에 `data-os`가 붙어 있어야
첫 화면이 안드로이드 모양으로 한 번 그려졌다가 바뀌는 깜빡임이 없음.

### 화면 전환: `<Routes>` 하나로는 안 되는 이유 (`ScreenStack.tsx`)
`<Routes>`는 현재 주소의 화면 **하나만** 그립니다. iOS push는 "나가는 화면"과 "들어오는 화면"이
동시에 움직여야 하므로, 방문 기록(`entries`)을 직접 들고 화면마다 `<Routes location={그 화면 주소}>`로 따로 그립니다.

핵심 트릭: 화면을 감싼 div의 `key`를 `location.key`로 둠 → 같은 화면은 배열에서 자리가 바뀌어도
**언마운트되지 않고 상태(스크롤 위치, 입력값)가 유지**됩니다. "들어오는 화면 → 다음 이동 때 나가는 화면"이 같은 인스턴스.

`useLayoutEffect`를 쓴 이유: 주소가 바뀐 직후 **화면에 그려지기 전에** 레이어 구성을 바꿔야
한 프레임 동안 엉뚱한 화면이 보이는 깜빡임이 없음. (`useEffect`는 그린 뒤에 실행됨)

### 스와이프로 뒤로가기
1. `pointerdown`이 왼쪽 24px 안에서 시작했을 때만 시작, `setPointerCapture`로 손가락이 화면 밖으로 나가도 계속 추적
2. 움직이는 동안: 위 화면은 `translateX(dx)`, 뒤 화면은 `-30% → 0%`로 비례 이동 (`transition: none`이어야 손가락에 딱 붙음)
3. 손 떼면 1/3 기준으로 확정/취소 → 이때만 `transition`을 켜서 마무리 애니메이션
4. 확정이면 애니메이션 끝난 뒤 `navigate(-1)`. 이미 화면을 밀어냈으니 pop 애니메이션은 `skipAnim`으로 건너뜀
5. **깜빡임 주의**: `navigate(-1)` 직후 바로 드래그 상태를 지우면, 주소가 실제로 바뀌기 전 한 프레임 동안
   밀려났던 화면이 제자리로 튀어나옴 → 드래그 상태는 주소가 바뀐 뒤(layout effect 안에서) 지움

`touch-action: pan-y`: 세로 스크롤은 브라우저가, 가로 움직임은 우리 코드가 받도록.

### 뒤에 깔린 화면 문제 → `LayerContext`
스와이프 중엔 뒤 화면(예: 홈)이 미리 마운트됩니다. 그 화면이 마운트되자마자
- 상태바 색을 바꿔버리거나(아직 위 화면이 보이는데 상태바만 검정),
- AI 배너 방문 횟수를 세버리면(스와이프 취소해도 문구가 넘어감) 안 됨.

그래서 각 레이어에 `active`(맨 위인지)를 Context로 내려주고, `useStatusBar`와 `AiPill`은 `active`일 때만 동작.
스와이프가 확정되면 같은 인스턴스가 `active=true`로 바뀌면서 그때 실행됩니다.

### Liquid Glass 탭바
- 유리 질감 = `background: rgba(...)` 반투명 + `backdrop-filter: blur() saturate()` + 위쪽 1px 흰 하이라이트(`inset box-shadow`)
- 스크롤 방향 감지: 이전 `scrollTop`과 비교. 6px 미만 움직임은 무시(안 그러면 손떨림에 탭바가 깜빡거림)
- 축소: 탭바 `width` transition + 선택 안 된 탭은 `flex: 0; opacity: 0`

### 안전영역(safe area)
실제 아이폰에서 열면 `env(safe-area-inset-top/bottom)`으로 노치·홈 인디케이터 영역을 피합니다.
`index.html`의 `viewport-fit=cover`가 있어야 `env()` 값이 0이 아니게 나옵니다.
하단 고정 버튼은 `bottom: max(18px, calc(var(--safe-bottom) + 4px))`로 두 OS 모두 대응.

## 10. 부드럽게 만들기 (성능)

### 측정부터

| 상황 | 수정 전 | 수정 후 |
|---|---|---|
| 홈 스크롤 | 평균 43ms/프레임, 끊김 41 | 17ms, 끊김 2 |
| 내역 스크롤 | 54ms, 끊김 54 | 17ms, 끊김 1 |
| 계좌 상세 스크롤 | 25ms, 끊김 24 | 17ms, 끊김 1 |
| 스와이프 뒤로가기 | 32ms, 끊김 37 | 19ms, 끊김 2 |

60fps = 프레임당 16.7ms 안에 끝나야 합니다.

### 원인 1: 매 프레임 setState
스크롤 위치를 state로 들고 있으면 스크롤할 때마다(초당 60번+) 화면 **전체**가 다시 렌더링됩니다.
- 매 프레임 바뀌는 값(패럴랙스 위치) → `ref`로 DOM 스타일을 직접 바꿈 (`useScrollFrame`)
- 켜짐/꺼짐 값(맨 위로 버튼, 탭바 축소) → 바뀌는 순간에만 setState. 같은 값으로 setState 하면 React가 리렌더를 건너뜀
- 스와이프 손가락 위치도 ref + `requestAnimationFrame`으로 프레임당 한 번만 DOM에 반영

### 원인 2: 한 글자마다 화면 전체 리렌더
타이핑 효과(`useTypewriter`)를 화면 컴포넌트에서 바로 쓰면 글자 하나마다 화면 전체가 다시 그려짐.
→ `<TypedText>`라는 작은 컴포넌트로 분리해서 그 `<span>`만 다시 그리게. **state는 필요한 곳에 최대한 가깝게(아래로).**

### 원인 3: 전환 중 화면 내용까지 리렌더
`ScreenStack`이 리렌더될 때 각 화면도 같이 다시 계산되던 것 → `LayerContent`를 `memo`로 감싸서
주소와 active가 같으면 건너뜀.

### 원인 4: 레이아웃/페인트를 부르는 애니메이션
브라우저는 `transform`과 `opacity`만 바뀌면 GPU **합성(composite)** 단계만 다시 하면 되지만,
`width`·`max-width`·`filter`·`background-position`이 바뀌면 레이아웃이나 다시 칠하기(paint)가 매 프레임 일어남.
- 스플래시 워드마크 `max-width` 펼치기 → 최종 위치에 미리 배치하고 `transform`으로만 이동
- 이전 화면 어둡게 `filter: brightness()` → 검은 막(`.layer__dim`)의 `opacity`
- 스켈레톤 반짝임 `background-position` → 빛줄기(`::after`)를 `transform`으로 이동
- 움직이는 동안만 `will-change: transform` (항상 켜두면 GPU 메모리 낭비)

### 녹화 영상이 끊겨 보였던 이유 (앱과 별개)
이전 영상은 Playwright 녹화 기능(약 25fps 제한)으로 찍었고, 스크롤도 50px씩 뚝뚝 움직였습니다.
이번엔 가상 디스플레이에 실제 브라우저를 띄워 ffmpeg로 60fps 캡처했고, 스크롤은 손가락으로 튕기듯
감속 곡선으로 움직였습니다. 컨테이너에 GPU가 없어서 녹화할 때만 페이지 시간을 3배 느리게 흘려 찍은 뒤
3배속으로 되돌렸습니다(앱 코드는 그대로). 큰 움직임 구간에서 58~60fps가 나옵니다.

## 11. 이미지 에셋 다루기 (직접 그리지 않기)

실무에서 아이콘·로고·사진은 코드로 그리지 않고 **디자이너가 준 파일을 넣습니다.**
이 프로젝트도 그렇게 바꿨고, 공개 저장소라는 제약 때문에 두 단계로 나눴습니다.

### 슬롯(자리) 구조 — `src/assets/Asset.tsx`
화면엔 `<Asset slot="bank-nh" />`처럼 **자리 이름만** 둡니다. 실제 파일은 이 순서로 찾습니다.
1. `src/assets/local/bank-nh.light.png` — 지금 테마 전용 실제 이미지
2. `src/assets/local/bank-nh.png` — 테마 공통 실제 이미지
3. 기본 에셋 — 저장소에 포함된 Microsoft Fluent 3D 이모지 (MIT 라이선스라 공개해도 됨)

`local/`은 `.gitignore` 처리돼 있어서 브랜드 로고·광고 사진이 공개 저장소에 올라가지 않습니다.

### `import.meta.glob` — "있는 파일만" 빌드할 때 고르기
```ts
const files = import.meta.glob<string>("./local/*.{png,jpg,webp}", { eager: true, import: "default" });
```
Vite가 **빌드할 때** 폴더를 훑어서 있는 파일만 번들에 넣고 URL을 줍니다.
- `<img src="/local/x.png" onError={...}>` 방식(예전 광고 사진)은 파일이 없으면 404 요청이 나가고,
  대체 이미지로 바뀌는 순간 **깜빡**입니다. glob은 둘 다 없음.
- 대신 파일을 추가/삭제하면 `npm run build`를 다시 해야 반영 (개발 서버는 자동)

### 테마마다 배경이 다른 아이콘
손 아이콘은 라이트에선 연회색 원, 다크에선 진회색 원 위에 있습니다. 방법 두 가지:
- **테마별 파일** (`ai-saving.light.png` / `ai-saving.dark.png`): 원 색 자체가 디자인일 때
- **배경을 투명하게 따기** (`colorkey`): 손·티머니·별은 회색 배경을 투명하게 만들어 파일 하나로 두 테마에 씀.
  원 배경은 CSS(`background: var(--home-icon-bg)`)가 그림

### 영상/스크린샷에서 잘라내기 — `scripts/extract-assets.sh`
ffmpeg만으로: 자르기(`crop`) → 확대(`lanczos`) → 원형 마스크(`geq`로 원 밖 alpha=0) /
배경 투명화(`colorkey`) / 가장자리 페이드. 좌표를 원본 폭 대비 비율로 계산하므로 더 큰 해상도의
같은 화면에도 그대로 동작합니다. 스크린샷(720px)이 영상(480px)보다 선명해서 홈 아이콘은 스크린샷에서 땁니다.

### 실제 이미지와 기본 이미지의 "모양 차이" 흡수
잘라낸 캐릭터 일러스트는 말풍선 바로 위에서 잘려 있지만, 기본 에셋(이모지 3개)은 말풍선과 많이 겹쳐야 자연스럽습니다.
`.asset--local` 클래스로 어떤 게 들어왔는지 CSS가 알 수 있게 해서 겹침 정도를 다르게 줬습니다.

## 12. 백엔드 — Express + SQLite (`server/`)

### 구조
```
화면 ──useApi("/api/home")──▶ fetch (+헤더 X-Profile) ──▶ Express (server/index.mjs) ──▶ SQLite (server/data/profiles/<id>.db)
🔔 패널 ──api.addBankAccount()──▶ POST /api/accounts ──▶ 201 Created
```
- 개발: `npm run dev` = API 서버(8787) + Vite(5173) 동시 실행. Vite가 `/api`를 8787로 넘겨줌(`vite.config.ts`의 proxy)
- 배포: `npm run build` 후 `npm start` → **서버 하나(9101)** 가 `/api`와 `dist/` 화면을 같이 줌.
  화면 주소(`/account/main` 등)로 바로 들어와도 `index.html`을 돌려줘서 새로고침이 안 깨짐(SPA fallback)
- DB는 Node 22에 들어있는 `node:sqlite` 사용 → 설치할 네이티브 모듈 없음. 비어 있으면 홍길동 예시 데이터로 자동 채움

### 테이블
```
profile      (id=1, user_name, card_last4)
accounts     (id, kind: main|external, bank_code, number, balance, badge, safebox, sort)
transactions (id, account_id → accounts ON DELETE CASCADE, at, merchant, amount, tag)
payees       (id, bank_code, number, holder, favorite, UNIQUE(bank_code, number))
transfers    (id, from_account_id → accounts CASCADE, bank_code, number, holder, amount, memo_to, memo_me, at,
              out_tx_id → transactions SET NULL, in_tx_id → transactions SET NULL)
```
- **CASCADE**: 다른 은행 계좌를 지우면 그 계좌의 거래도 DB가 알아서 같이 지움
- **트랜잭션**: 거래 추가 = "거래 INSERT + 잔액 UPDATE" 두 문장. `transaction(fn)`으로 묶어서 둘 중 하나만 되는 일이 없게
- **은행별 규칙**은 `banks.mjs` 한 곳에: 이름, 대표색, 계좌번호 자릿수 패턴(신한 3-3-6, 국민 6-2-6 …).
  서버는 숫자만 받아서 패턴대로 `-`를 넣어 저장 → 화면은 형식 걱정 없음

### 연습 포인트
- **상태코드 의미**: 만들기 성공은 201, 지워서 돌려줄 게 없으면 204, 입력 잘못은 400, 없으면 404, 이미 있으면 409
- **서버 검증**: 패널에서 막아도 서버가 다시 검사 (금액 0, 1천만원 초과, 잔액 부족, 계좌번호 자릿수, 중복 계좌…)
  → `curl`로 직접 이상한 값을 보내보면 왜 필요한지 보임
- **파생 데이터**: "거래 후 잔액"은 저장하지 않고 조회할 때 계산 → 거래를 지우거나 잔액을 바꿔도 내역이 항상 맞음
- **캐시 무효화**: POST/PATCH/DELETE 성공 → `invalidate()` → `useApi`를 쓰는 모든 화면이 자동으로 다시 요청
  (React Query의 `invalidateQueries`, SWR의 `mutate`가 하는 일과 같음)
- **stale-while-revalidate**: 한 번 받은 데이터는 캐시에서 즉시 보여주고 뒤에서 새로 받음.
  스플래시 동안 `prefetch("/api/home")` 해 두어서 홈은 처음부터 바로 뜸

### 🔔 관리 패널 — "버튼과 숫자 입력만"
화면(홈, 계좌, 거래 상세)은 **보기 전용**이고, 바꾸는 건 전부 종 버튼 패널에서 합니다.
- **기본**: 지금 프로필·프로필 바꾸기, Galaxy/iPhone, 시스템/라이트/다크, 이름·카드 끝 4자리, 빈 상태로/예시 데이터로
- **계좌**: 계좌를 눌러 펼치면 잔액 수정, 다른 은행이면 계좌번호 수정·삭제. 은행선택 목록(이체 화면과 같은 컴포넌트)에서 골라 새 계좌 추가
- **받는 분**: 이체 때 계좌번호로 찾을 상대 계좌(은행·번호·예금주) 관리
- **거래**: 계좌 칩 → 금액(+1천/+5천/+1만/+5만) → 거래처 칩 → 종류 → 입금하기/출금하기. 최근 거래 ✕로 삭제

입력칸이 숫자만 받고 자동으로 `-`·`,`를 넣는 이유: "형식 맞추기"를 사용자에게 시키지 않기.
같은 패턴 배열(`[3,3,6]`)로 서버는 저장 형식을, 화면은 입력 중 표시를 만든다.

### 수정 폼에서 effect로 값 채우지 않기
"데이터가 오면 `useEffect`에서 `setForm(data)`"은 흔하지만, 렌더가 한 번 더 일어나고 재요청 때 입력 중인 값을
덮어쓸 수 있습니다. 대신 `draft` state를 `null`로 두고 `draft ?? account.balance`를 보여줌 →
안 건드렸으면 서버 값, 건드리면 입력값. 저장하면 `setDraft(null)`.

## 13. 새 영상 디테일 구현 방법

### 글자 위를 지나가는 색 띠 (`.cashback__sweep`)
```css
background: linear-gradient(90deg, 글자색 0 22%, 노랑, 초록, 하늘, 파랑, 하늘, 초록, 노랑, 글자색 78% 100%);
background-size: 400% 100%;      /* 그라데이션을 글자 폭의 4배로 */
-webkit-background-clip: text;   /* 배경을 글자 모양으로 오려냄 */
color: transparent;
animation: cash-sweep 10s linear infinite;  /* 0~24%(2.4초)만 100%→0%로 이동, 나머지는 멈춤 */
```
양 끝이 원래 글자색이라 멈춰 있을 땐 그냥 검은 글씨. 다크 모드에선 `var(--home-text)`가 흰색이라 그대로 동작.

### 무한 루프 캐러셀
`[마지막 복제, 1, 2, 3, 첫 번째 복제]`로 깔고, 복제본에 도착하면 `transitionend`에서 애니메이션을 끈 채
진짜 위치로 순간이동. 자동 넘김 타이머는 `index`가 바뀔 때마다 새로 걸어서, 손으로 넘긴 직후 바로 또 넘어가지 않게.
드래그 중엔 리렌더 없이 DOM transform만 직접 바꿈 (10번 성능 해설과 같은 원리).

### 흰 배경 이미지 녹이기 + 함정
배너 이미지는 흰 배경째 잘려 있습니다. `mix-blend-mode: multiply`는 흰색을 투명처럼 만들어 주는데,
**부모에 `will-change: transform`이 있으면 독립 레이어(투명 배경)가 생겨서 섞일 대상이 없어 효과가 사라집니다.**
레이어에 배경색을 깔아서 해결. (결국 실제 앱 배경이 흰색이라 지금은 자연스럽게 맞음)

```
홈 [이체] ─▶ /transfer?from=main        내 계좌 / 최근 이체 / [+ 계좌번호 직접입력]
              └ 시트: 은행선택 → 계좌번호(키패드) → GET /api/transfer/lookup → 예금주 이름
           ─▶ /transfer/amount (state: {from, to})   금액 키패드 → [다음] → 표기 2줄 → [다음] → 확인 시트
           ─▶ POST /api/transfers ─▶ /transfer/done (replace)   [확인] = navigate(-2) → 홈
```
- **받는 분 정보는 주소가 아니라 `location.state`로** 넘김: 이름·은행·번호 묶음이라 URL에 넣기 번거롭고,
  ScreenStack이 화면마다 자기 location을 들고 있어서 뒤로 갔다 와도 그대로 남음.
  새로고침하면 state가 없으니 홈으로 돌려보냄
- **완료 화면은 replace**: 완료 후 뒤로가기로 금액 화면에 돌아가 "한 번 더 보내기"가 되면 안 되니까.
  기록이 [홈, 이체, 완료]가 되므로 확인 = `navigate(-2)`
- **시트는 항상 DOM에 두고 transform으로만 올리고 내림** (`components/Sheet.tsx`) → 닫힐 때도 애니메이션.
  시트가 열리면 `useStatusBar("#808080")`로 상태바까지 어둡게 (영상처럼)
- **키패드 입력 계산은 순수 함수 하나**(`lib/keypad.ts`의 `applyKey`): 앞자리 0, 최대 길이, 지우기를 한 곳에서.
  금액 화면(00 있음)과 계좌번호 시트(빈칸)가 같은 함수를 씀
- **금액이 위아래로 안 움직이게**: "일 200,000원" 안내 줄이 사라져도 빈 줄로 자리를 남겨 둠

### 예금주 조회를 어떻게 흉내 냈나
진짜 은행은 계좌번호를 넣으면 금융결제원 망으로 상대 은행에 "이 계좌 주인 누구야?"를 물어봅니다.
여기선 그 상대 은행 역할을 `payees` 표가 합니다. 🔔 패널에서 미리 등록한 계좌만 이름이 나오고,
없으면 404 `ACCOUNT_NOT_FOUND` → "입력하신 계좌정보를 확인해 주세요". 내 계좌(카카오뱅크 통장·추가한 다른 은행)는 등록 없이 찾아짐.

### 서버에서 꼭 다시 검사하는 것
- 받는 분은 **화면이 보낸 이름을 믿지 않고** 서버가 (은행, 번호)로 다시 찾는다 → 이름 위조 불가
- 잔액 부족, 같은 계좌로 보내기, 1천만원 초과
- 출금 거래 + (내 계좌면) 입금 거래 + 잔액 두 군데 + 이체 기록 → **`transaction()` 하나로 묶음**.
  중간에 하나라도 실패하면 전부 ROLLBACK → "돈은 빠졌는데 안 들어갔다"가 생길 수 없음
- 통장에 찍히는 이름: 내 통장엔 `나에게 표기`(없으면 받는 분 이름), 받는 통장엔 `받는 분에게 표기`(없으면 내 이름)

### 최근 이체 = 계산
"최근 이체 목록"을 따로 저장하지 않고 `transfers`를 (은행, 번호)로 GROUP BY 해서 마지막 시각순으로 뽑음.
☆는 받는 분(`payees.favorite`)에 저장 → 받는 분 등록이 지워진 상대는 별을 못 누름.

### 예전 DB 고치기 (마이그레이션)
mini를 없애고 세이프박스를 추가하면서 테이블 모양이 바뀌었습니다. `CREATE TABLE IF NOT EXISTS`는 표가 이미 있으면
아무것도 안 하므로, VPS에 있던 bank.db는 `db.mjs` 맨 위에서 `PRAGMA table_info`로 컬럼을 확인하고
`ALTER TABLE ... ADD COLUMN safebox` / `DROP COLUMN mini_account_no` + mini 계좌 삭제(CASCADE로 거래도 정리)를 직접 실행합니다.
진짜 서비스에선 이걸 번호 붙은 마이그레이션 파일(001_..., 002_...)로 관리합니다.

## 15. 프로필 — 넷플릭스처럼 고르고, 프로필마다 따로 저장 (`src/profile/`, `server/db.mjs`)

### 데이터를 어떻게 나눴나: 프로필마다 DB 파일 하나
```
server/data/app.db               profiles(id, name, avatar, color, os, theme, created_at)
server/data/profiles/p1a2b3c4.db  그 프로필의 profile/accounts/transactions/payees/transfers
```
- 다른 방법은 모든 표에 `profile_id` 칸을 넣는 것. 그러면 **모든 쿼리에 `WHERE profile_id = ?`를 빠짐없이** 붙여야 하고,
  하나라도 빼먹으면 다른 프로필 데이터가 보임. 파일을 나누면 기존 쿼리를 그대로 쓸 수 있고, 삭제도 파일 지우기로 끝
- 대신 프로필끼리 데이터를 합쳐 보는 기능(전체 통계 등)은 어려워짐 → 이 앱엔 필요 없어서 파일 분리를 택함

### 요청마다 "어느 DB?" — 헤더 + AsyncLocalStorage
- 화면은 모든 요청에 `X-Profile: <id>` 헤더를 붙임 (`api/client.ts`)
- 서버 미들웨어가 헤더로 그 프로필 DB를 열고 `runWithDb(그 DB, next)`로 나머지 처리를 감쌈.
  그 안에서 불리는 함수들은 그냥 `db()`만 부르면 지금 요청의 DB가 나옴 (Node의 `AsyncLocalStorage`:
  요청 하나의 흐름을 따라다니는 "보이지 않는 인자". `setTimeout`으로 미뤄도 따라감)
- **id가 파일 이름이 되므로 형식 검사 필수**: `/^p[0-9a-f]{8}$/`. 안 하면 `X-Profile: ../../server/x` 같은 값으로
  엉뚱한 파일을 열 수 있음 (경로 조작 공격)
- DB 연결은 `Map`에 열어 두고 재사용. 프로필을 지울 때는 연결을 닫은 뒤 `-wal`, `-shm` 파일까지 지움

### 화면 쪽: 언제 다시 고르게 하나
- 고른 프로필 id는 **sessionStorage**: 탭을 닫으면 사라짐 → 다음에 들어오면 다시 고르기(넷플릭스처럼).
  새로고침은 같은 세션이라 유지됨
- 기기/테마는 앱이 켜질 때 한 번 정해지는 값(`OS`, `THEME` 상수)이라, 프로필 설정이 지금과 다르면
  `/?os=…&theme=…`로 **다시 불러와서** 적용. 켜질 때마다 지금 설정을 그 프로필에 PATCH 해 두므로
  스위치나 🔔에서 바꾼 것도 자동으로 그 프로필에 저장됨
- 쓰던 프로필이 다른 창에서 지워졌으면 그 PATCH가 404 → 프로필 고르기로 돌려보냄

## 16. 화질과 누끼 — 원본이 전부다

- 화면 녹화는 폭 480px(= 화면 1dp당 1.33px)이라, 34dp 아이콘이 45px밖에 안 됨. 2배 화면(레티나)에선 68px가 필요해서 흐림.
  **스크린샷(720px, 1dp당 2px)** 에서 자르면 딱 2배 화면에 맞는 선명도. 업스케일은 흐린 걸 크게 할 뿐 선명해지지 않음
- **누끼(배경 빼기)**: 흰 배경을 그냥 `colorkey`로 지우면 그림 안의 흰 부분(카드 무늬)까지 구멍이 남.
  → 테두리에서부터 배경색을 따라 들어가는 **flood fill**로 "바깥과 이어진 흰색"만 지움 (`scripts/extract-screenshots.py`)
- **흰 테두리(halo) 없애기**: 경계 픽셀은 그림 색과 흰 배경이 섞여 있어서, 투명하게만 하면 다크 모드에서 하얀 테두리가 보임.
  섞인 색 = 원래색·α + 흰색·(1-α) 를 거꾸로 풀어 원래색과 α를 되찾음 (`(c - (1-α)·255) / α`). 포토샵의 "Defringe"와 같은 원리
- 동그라미 아이콘은 4배 크기로 원을 그린 뒤 줄여서 마스크로 → 가장자리가 계단 없이 부드러움. 1px 안쪽까지만 잘라 흰 테두리 방지
- 특수 글자체 로고(AND2BLE)는 글꼴로 흉내 내지 말고 이미지로. 노란 배경의 검은 글자라 초록 채널 밝기로 투명도를 계산
  (노랑 G≈222, 검정 G≈0) → 글자 가장자리의 반투명까지 살아 있음

## 17. 캡쳐모드 — CSS 속성 하나로 켜고 끄기

`<html data-capture="on">`만 붙이면 CSS가 폰 테두리·그림자·둥근 모서리·아래 스위치를 숨기고 화면을 가운데에 둠.
React 상태가 아니라 DOM 속성이라 **새로고침 없이** 바로 바뀌고, localStorage에 기억해서 다시 열어도 유지
(`src/platform/capture.ts`). 기기·테마도 같은 방식(`data-os`, `data-theme`)이라 규칙을 맞춤.

## 18. 화면 녹화 — 탭 화면 받아서 폰만 자르기 (`src/platform/recorder.ts`)

1. `navigator.mediaDevices.getDisplayMedia({ preferCurrentTab: true })` → 사용자가 "이 탭"을 허락하면 탭 화면 영상(MediaStream)
   - 버튼 클릭 안에서 바로 불러야 함(보안상 사용자 동작 필요). 크기를 안 정하면 720p 정도로 낮춰 주므로 `width/height: { ideal: 큰 값 }`
2. 폰 부분만 자르기
   - 크롬/엣지 **Region Capture**: `CropTarget.fromElement(폰)` → `track.cropTo()` — 브라우저가 잘라 줘서 가장 선명하고 가벼움
   - 그 밖의 브라우저: `<video>`로 받아 매 프레임 `<canvas>`에 폰 영역만 `drawImage` → `canvas.captureStream(60)`
3. `MediaRecorder`로 녹화. `isTypeSupported`로 mp4(h264) → 안 되면 webm. 멈추면 Blob → `<a download>`로 저장
   - 브라우저의 "공유 중지"로 멈춰도 `track`의 `ended` 이벤트에서 저장
4. 녹화 상태는 React 바깥 모듈 변수 + `useSyncExternalStore` → 패널(시작)과 위쪽 막대(정지)가 따로 떨어져 있어도 같은 상태를 봄
5. "녹화 중" 막대는 폰 바깥 `position: fixed` → 잘린 영역 밖이라 영상에 안 찍힘. 녹화하는 동안 캡쳐모드로 테두리도 숨김

폰 브라우저는 `getDisplayMedia`가 없어서 녹화 불가 → 버튼 대신 "폰 자체 화면녹화를 쓰세요" 안내.


### 앱 켜지는 모습부터 녹화 + 폰에서 깨지던 문제
- 녹화가 실제로 시작되면 `bank:restart` 이벤트로 App 이 `off`(검은 화면) → 다음 프레임에 녹화 시작 → 0.6초 뒤 시작화면.
  새로고침하면 녹화가 끊기므로 페이지는 그대로 두고 App 의 boot 상태만 처음으로 돌림 (주소도 `/`).
- 안드로이드 크롬은 '이 탭'이 아니라 **폰 화면 전체**가 들어오고(402×874 처럼 작게), 하드웨어 H.264 로 만든 mp4 는
  P 프레임이 깨져 거의 회색 화면이 됨. → 코덱은 webm(VP9/VP8), 원하는 크기를 화면 해상도(screen × dpr)로 요청,
  전체화면으로 바꿔 '화면 = 페이지'로 만든 뒤 `visualViewport` 기준으로 폰 영역을 잘라 캔버스로 녹화.
  전체화면은 버튼 누름 안에서만 켤 수 있어서(공유 허락 창이 그 기회를 써 버림) "화면을 누르면 시작"을 한 번 더 받음.
- `recorder.start(1000)`(1초마다 조각) 대신 `start()` — 조각 mp4 는 일부 플레이어에서 앞부분이 깨짐.

## 19. 두 번째 앱 (NH 콕뱅크) — 같은 코드, 서버(포트)만 따로 (`src/nh/`, `server/db.mjs`)

### 서버 하나 = 앱 하나
처음엔 프로필 화면에서 앱을 고르고 `X-App` 헤더로 DB를 나눴는데, 두 앱을 **포트로 완전히 분리**하는 쪽으로 바꿨습니다.
`APP=nh`(또는 `--app nh`)로 띄우면 그 서버는 콕뱅크만: 데이터 폴더가 `server/data-nh/`라서 프로필 목록부터 따로.
**API 코드는 그대로** — `/api/home`, `/api/transfers`가 두 앱에서 똑같이 동작하고 데이터만 다릅니다.
앱마다 다른 것만 `db().app === "nh"`로 분기(1일 송금 한도, 받는 분 목록의 `dailyRemaining`).
`SEEDS = { kakao: {...}, nh: {...} }` — 새 프로필, 되돌리기(`/api/reset`), 첫 실행 예시 데이터가 앱에 맞게.

### 화면은 빌드 하나 — 어느 앱인지는 서버가 HTML에 끼워 줌
`npm run build` 결과(dist)는 두 서버가 같이 씁니다. 서버가 `index.html`을 줄 때
`<script>window.__BANK_APP__ = "nh"</script>`를 넣고(`express.static(..., { index: false })`로 `/`도 직접 처리),
화면은 `session.ts`의 `APP` 상수로 읽습니다. 개발 서버(Vite)엔 이 단계가 없어서 `npm run dev:nh`가 `VITE_APP=nh`를 넣어 줍니다.
포트가 다르면 브라우저 입장에선 **다른 사이트(origin)** 라서 sessionStorage·localStorage(고른 프로필, 기기, 테마)도 저절로 따로.

### 화면: 라우트 묶음을 통째로 바꾸기
`App.tsx`는 `APP`에 따라 `ScreenStack`에 다른 `render` 함수(`renderRoute` / `renderNhRoute`)를 줍니다.
주소(`/send`, `/history/:id`)는 겹쳐도 됩니다 — 한 서버에선 한 앱만 그려지니까.

### 한 화면이 단계별로 바뀌는 송금 (`NhSend`)
카카오뱅크 이체는 화면마다 주소가 달랐지만, 콕뱅크 영상은 **같은 화면의 위쪽이 바뀌고 시트가 올라오는** 구조라
`stage: "who" | "amount" | "memo"` 상태 하나로 그렸습니다. 뒤로가기(←)도 단계를 하나씩 되돌립니다.
확인 화면부터는 다시 주소(`/send/confirm` → `/send/done`은 `replace`)로 나눠서 브라우저 뒤로가기와 맞춥니다.

### "6개월간 보낸 적 없는 분" 판단
서버가 최근송금 목록에 마지막으로 보낸 시각 `lastAt`을 같이 주고, 화면이 `Date.now() - lastAt < 183일`인지 계산.
내 계좌로 보내는 건 확인 시트를 건너뜁니다. (저장하지 말고 계산하기 — 7번과 같은 원칙)

### 거래메모 = 자동 저장
`PATCH /api/transactions/:id {memo}`. 입력이 0.5초 멈추면 저장(디바운스: effect 안의 `setTimeout` + cleanup에서 `clearTimeout`).
송금 확인 화면에서 쓴 메모는 송금 응답의 `outTxId`(내 통장 출금 거래 id)로 바로 저장합니다.

### 함정: 짧은 클래스 이름 충돌
완료 화면의 체크 아이콘 뒤에 흰 네모가 생겼는데, 카카오뱅크 완료 화면 CSS의 `.done { background: #fff }`가
콕뱅크의 `className="done"`에도 걸린 것. CSS는 전역이라 **`done`, `on` 같은 짧은 이름은 BEM 수식어(`nh-done__mark--done`)로**.

### 이미지: 사각형 자르기 vs 누끼
처음엔 콕뱅크가 다크 화면 하나뿐이라 그림 대부분을 **사각형 그대로** 자르고 CSS 바탕색을 같은 색으로 맞췄습니다.
라이트모드가 생기고 에셋 검수(2026-11)를 거치며 지금은 거의 다 **3배 크기의 투명 누끼**이고, 파일은 잉크 상자만큼 잘려 있어
`NhImg` / `CrispImg` 의 `ink` 값(예전 자리 안 잉크 상자)으로 같은 자리에 놓입니다 (아래 24장).
단, 지식콕·금융콕 카드는 바탕이 위→아래 살짝 그라데이션이고 둥근 모서리가 걸려서 테두리가 보였음 →
`cutout_on(..., also=[페이지색])`으로 카드색과 페이지색을 둘 다 투명하게 (`scripts/extract-nh.py`).

### 버튼 누르면 "어둡게 + 점 3개" (`src/nh/loading.ts`)
콕뱅크는 메뉴를 누르면 바로 넘어가지 않고 화면 전체가 어두워진 채 점 3개가 잠깐 돈 뒤에 다음 화면이 뜹니다.
화면마다 상태를 두지 않고 **작은 전역 저장소**(`count` + 구독 함수들)를 만들어 `useSyncExternalStore`로 읽고,
`App`이 그 위에 덮개(`NhLoadingLayer`) 한 장만 그립니다. 화면에선 `navigate` 대신 `useNhGo()`의 `go(주소)`를 쓰면
`withNhLoading` → 최소 0.55초 보여준 뒤 이동. 서버 요청도 `withNhLoading(() => api.xxx())`로 감싸면 같은 모양.
녹화를 프레임 단위로 보면 **화면은 덮개 아래에서 바뀌고**, 덮개는 새 화면이 한 번 그려진 뒤에 걷힙니다
(`navigate` → 90ms → `requestAnimationFrame` 두 번 → `count--`). 그래서 덮개가 걷히는 순간 이미 다음 화면이 보임.

### 은행 로고 흰 테두리
은행 아이콘은 카카오뱅크(흰 화면)에서 잘라 와서 가장자리에 흰 픽셀이 남아 있었고, `BankIcon`이 흰 바탕+옅은 테두리까지 깔아서
어두운 콕뱅크 화면에선 흰 링이 보였음 → 콕뱅크 전용 `NhBankIcon`: 동그라미로 자르고(`overflow: hidden; border-radius: 50%`)
그림을 1.1배 키워서 가장자리를 원 밖으로 밀어냈었음. 지금은 공용 로고가 원이 캔버스에 꽉 찬 150px(흰 테 없음)이라 확대도 뺌.
농협은 콕뱅크 목록의 노란 동그라미(`nh-bank.png`)를 따로 잘라 씀.

### 숨은 함정: 세로 flex 안의 `overflow: auto`
거래내역 칩 줄에 아래 여백을 늘렸는데 화면에 안 바뀜. 화면이 `flex-direction: column`이고 칩 줄이 `overflow-x: auto`라
**min-height가 0**이 되어서, 내용이 화면보다 길면 칩 줄이 세로로 눌려 줄어든 것. `.screen.nh > * { flex-shrink: 0 }`.

### 픽셀 단위로 맞추기 (스크린샷·녹화와 겹쳐 보기)
- **기준 크기부터**: 스크린샷 폭 720px, 녹화 480px → 같은 화면이 384dp가 되는 비율(1.875, 1.25)이라 폰 폭은 384dp.
  콕뱅크일 때만 `<html data-app="nh">`로 프레임을 384 × 853.33으로 바꿈 (카카오뱅크 412는 그대로).
- **글꼴**: 글자 모양을 비교해 Pretendard로 확인. 자간 -0.01em, 굵기 400/500/600만 씀.
- **0.5dp 선**: 크롬은 1px보다 얇은 `border`를 1 CSS px로 올려 그려서 두꺼워짐 →
  `box-shadow: inset 0 0 0 0.5333px 색`으로 그리면 얇은 선이 그대로 나옴.
- **소수점 위치**: `top`/`left`/`height`는 CSS px 단위로 반올림돼 그려지는 경우가 있어서, 0.3px 같은 미세 조정은
  `translate`로 (예: 헤더 제목 `translate: 0 -1.4px`).
- **움직임**: 녹화를 0.25초(필요하면 프레임마다) 잘라서 위치·불투명도를 재고 곡선을 맞춤.
  안드로이드 화면 전환은 80ms(들어올 때)/100ms(나갈 때) 직선 페이드, 키패드 시트는 열림 410ms `cubic-bezier(.2,1,.4,1)`,
  닫힘은 끝까지 내려가지 않고 176dp만 내려가며 200ms 동안 투명해짐.
- **확인 → 뒤로**: 확인 화면에서 X를 누르면 송금 화면이 처음이 아니라 **방금 단계(메모 입력)** 로 돌아옴.
  이동하기 직전에 지금 단계를 `navigate(같은 주소, { replace: true, state: { restore } })`로 기록해 두고 다시 그릴 때 꺼냄
  (`src/nh/nhSendRestore.ts`). "받는 분을 다시 입력할게요."만 처음 단계부터.
- 비교는 `overlay`(두 그림 반씩 섞기)와 가장자리(edge) 비교로. 남는 차이는 가짜 이름·번호 글자와 상태바 시계뿐.

### 일반 홈 (청소년 홈이 아니라) — 공식 사진 + 녹화로 다시 만들기
처음 만든 홈은 알고 보니 **청소년 모드** 홈이었습니다. 콕뱅크는 모드(일반·청소년·큰글…)마다 홈이 달라서,
앱스토어 공식 스크린샷(밝은 모드, 계좌 여러 개)으로 구조를 보고 사용자가 보내 준 다크모드 녹화로 크기·색을 맞췄습니다.
- **긴 화면 재기**: 스크롤하는 녹화 프레임끼리 겹치는 부분을 찾아(밝기 차가 가장 작은 세로 이동량) 한 장의 긴 페이지 그림으로 이어 붙인 뒤
  그 위에서 위치를 잼. 위에 붙어 있는 헤더(접힌 계좌 카드) 아래만 비교해야 맞음.
- **둥근 모서리 함정**: 카드 위·아래 끝을 카드 왼쪽 끝 가까이(x 30)에서 재면 모서리 곡선 때문에 4~5dp 안쪽으로 잡힘 → 카드 가운데 쪽에서 재기.
- **가운데 카드만 큰 가로 목록**(콕추천): 카드 상자는 모두 같은 높이(116.4)로 두고 흰 바탕을 `clip-path: inset(5.9px 0 round 20px)`로
  깎았다가 가운데 카드만 0 으로 → 글자 위치는 그대로고 바탕만 커짐.
- **접히는 위 영역**: 스크롤이 140dp 를 넘으면 위에 작은 카드(번호 ⌄ / 잔액 [송금])를 따로 그려 붙이고, 탭바는 아래로 숨기고 ↑ 버튼을 보임.
- **글자 위치 공식**: Pretendard 는 `line-height: 1` 일 때 한글 잉크 가운데가 top + 0.54em → 녹화에서 잰 잉크 가운데로 top 을 바로 계산.
- **흰 카드 안 그림 자르기**: 카드가 흰색이라 바탕을 투명하게 할 필요 없이 사각형으로 자르되, 그림 옆 글자는 지움
  (무채색 어두운 픽셀 = 검정·회색 글자, 분류 글자는 그 색과 흰색 사이 색) — 화면에서 진짜 글자를 그 위에 다시 그림.
- **`.nh button { color: inherit }`(공용)**이 `.클래스` 하나짜리 글자색보다 우선이라 버튼 글자색이 안 바뀜 → 버튼 규칙 앞에 `.nh-gh-wrap`.

### 라이트모드 — "요소마다 같은 자리 색 재기" 도구
라이트 화면을 새로 그리지 않고 **같은 레이아웃에 색만** 바꿨습니다 (`src/nh/nh-light.css`, `html[data-theme="light"]` 아래).
1. 내 화면(다크)을 녹화와 같은 상태로 띄워, 보이는 요소마다 위치·배경색·글자색·선색을 뽑음 (Playwright + `getComputedStyle`)
2. 라이트 녹화의 같은 자리에서 배경 = 가장 많은 색, 글자/선 = 배경과 가장 다른 픽셀들의 가운데 값을 잼
3. "다크 색 → 라이트 색" 표가 나오면 공용 색 토큰(`--nh-text`, `--nh-field` …)부터 바꾸고, 하드코딩된 색은 규칙을 덮어씀
- **우선순위 함정**: `html[data-theme=light] .nh-as__value { color: 회색 }`가 `.nh-as__value.error { 빨강 }`보다 셀렉터가 세서
  잔액 부족 빨간 글씨가 회색이 됨 → 라이트 규칙은 `:not(.filled)`처럼 상태를 빼고 씀.
- **녹화가 검정인 화면**: 라이트 녹화에서 로딩·금액 키패드 시트 때 화면 전체가 새까맸는데, 같은 날 다크 녹화도 그랬고 전날 다크 녹화는 반투명 막.
  보안 화면(키패드)을 화면 녹화기가 가린 것으로 보고 실제 화면처럼 반투명 막(0.6) 그대로 둠.
- **다크에서 자른 그림**(완료 동전·메시지 타일·방패 등)은 바탕이 어두운 사각형 → 픽셀마다 가장 가까운 다크 바탕색과의 거리로
  덮인 정도를 어림해 라이트 바탕 위에 다시 섞음 (`scripts/nh-crops/light-variants.py`, `nhPic()`이 `-light` 그림을 고름).
- 상태바는 화면마다 `useNhStatusBar(다크색, { dim, black })` 하나로: 라이트면 흰 바탕 + 어두운 글자.

## 20. 로그인 · 관리자 계정 (`server/auth.mjs`, `src/auth/`)
- **세션 쿠키**: 로그인하면 임의 토큰을 `sessions` 표에 넣고 `HttpOnly` 쿠키로 줌. 쿠키는 포트를 구분하지 않아서
  (같은 주소의 9101·9103이 쿠키를 공유) 이름에 앱을 넣음: `bank_sid_kakao` / `bank_sid_nh`.
- **비밀번호**: `scrypt` + 계정마다 다른 salt, 비교는 `timingSafeEqual`. 같은 IP 에서 1분에 10번 틀리면 잠깐 막음.
- **모든 /api 앞에 로그인 확인 미들웨어**: 로그인 안 됨 401, 기간 끝 403 EXPIRED, 정지 403 DISABLED.
  화면은 `client.ts` 가 이 응답을 받으면 `auth.ts` 에 알려서 바로 로그인 화면으로 (서로 import 하면 순환이라 리스너 등록 방식).
- **프로필 = 계정 소유**: `profiles.owner_id`. 다른 계정의 프로필 id 를 `X-Profile` 로 보내도 "없는 프로필".
- **기간**: 만든 시각 + N일을 `expires_at` 에 저장 (영구는 NULL). 연장은 남은 기간 끝(이미 끝났으면 지금)에 더함.
- 첫 실행 때 관리자 계정을 만들고 주인 없는 예전 프로필을 관리자 것으로 (`ALTER TABLE ... ADD COLUMN owner_id`).

## 21. 세 번째 앱 (하나원큐) — 앱 하나 더 붙이기 (`src/hana/`, `server/db.mjs`)

콕뱅크 때 만든 "서버 하나 = 앱 하나" 구조라 앱을 하나 더 붙이는 데 필요한 건 네 군데뿐이었다.

1. **서버**: `APPS` 에 `hana` 추가 → 데이터 폴더 `server/data-hana/`, 기본 포트 9105, 예시 데이터(`seedHanaExample`, 전부 가상).
   API·표 모양은 그대로. 거래 목록에 "내가 보낸 이체면 받은 은행"(`toBank`)만 더 실어서 "타행송금(지역농축협)" 표기를 만든다.
2. **화면 고르기**: `APP` 에 따라 `ROUTES[APP]` (카카오 / 콕 / 하나) 와 시작화면만 바꿈. 로그인·프로필·관리 패널은 공용
   (`AppIcon`, `APP_NAME`).
3. **갤럭시 프레임**: 같은 갤럭시(384 × 853.33dp, 상태바 28 + 제스처바 15)라 콕뱅크용 규칙을 `data-app="hana"` 에도 걸었다.
   다른 점은 제스처바 색: 콕뱅크는 검정 띠, 하나원큐는 앱 바탕색(라이트 흰색 / 다크 #191a1c)이 아래까지 깔리고
   키보드·시트가 뜨면 그 색을 따라감 (`data-hana-kb`, `data-hana-dim`).
4. **화면**: 홈 · 이체(한 화면이 who → amount → memo 로 바뀌고, 계좌 입력·표시 수정·확인은 그 위에 덮는 페이지) · 완료 · 거래내역 · 상세.
   값은 녹화(480px → ×0.8) · 스크린샷(720px → ÷1.875) 에서 재고, 같은 크기로 찍은 클론 화면을 반투명으로 겹쳐서 맞췄다.

### 비밀번호 단계를 건너뛰는 이유
실제 앱은 '이체'를 누르면 비밀번호 자판이 뜨는데, 이 화면은 보안 화면(FLAG_SECURE)이라 갤럭시 녹화에 검은 화면으로 찍힌다.
그래서 클론은 버튼을 회색으로 바꾸고 원호 로딩(1.2초, `WAIT.send`)만 보여 준 뒤 바로 완료로 넘어간다 (`Confirm` 의 `send`).

### 확인 화면은 시트가 아니라 페이지
녹화 한 장면만 보면 아래에서 올라오는 시트처럼 보이지만(라이트 41.0초), 다음 프레임부터는 화면 전체를 덮는다.
그래서 시트처럼 아래에서 올라오되 맨 위까지 덮고, 올라오는 동안만 뒤를 옅게(0.2) 어둡게 한다.

### 아이콘 · 배경 (`scripts/hana-crops/icons.py`)

### 녹화가 가로로 1.0242배 늘어나 있다
처음 잰 값들이 화면마다 어긋났다 (금액 화면은 "+4.5px 밀림", 거래내역은 "393 폭 웹뷰라 오른쪽이 잘림" 같은 해석이 나옴).
화면 곳곳의 **원·정사각형 11개**(은행 로고 원, 체크 원, 아이콘 상자)의 가로/세로 비를 재 보니 전부 1.024 안팎 →
녹화기가 화면을 가로로 늘려 저장한 것. 오른쪽 끝 9px 는 잘려 있다.
- 변환: **클론 x = (녹화 x − 0.35) / 1.0242**, 폭·반경도 ÷1.0242, 세로는 그대로 (`src/ibk/theme.ts` 의 `ibkX`, `ibkW`).
- 비교 도구도 녹화 프레임을 이 식으로 되돌린 뒤 클론 화면과 반반 겹쳐 봄. 클론 x 375~384 는 녹화에 없는 부분.
- 그림을 자를 때도 4배로 키운 뒤 가로만 ÷1.0242 (`crops.py` 의 `STRETCH`). 안 그러면 원이 타원이 된다.

### 3버튼 폰 틀 · 픽셀 붙음
- 상태바 29.4 (#fafafa) + 앱 758.6 + 3버튼 바 44 (Ⅲ ○ <). `<` 는 앱 안 뒤로가기.
- 앱 영역 위끝이 29.4 라서 `top` 으로 놓은 아이콘·글자가 정수 픽셀로 반올림되며 0.4px 씩 어긋남 →
  아이콘은 `top: 0` + `transform: translate(x, calc(y + var(--ib-y0)))`(안드로이드 0.4px), 글자는 기준선으로 놓음:
  `.ibk-bl` 에 놓을 top 은 `ibkBlTop(녹화 기준선, 글자 크기, 상자 녹화 y)` (`theme.ts`). 처음엔 'top = 기준선 − 0.3418 × 크기'(Roboto ascent 비율)로
  잡았는데 Chrome 은 기준선을 **round(상자 위 y) + floor(A − (A+D)/2)** (A = round(0.927734·fs), D = round(0.244141·fs)) 에 붙여서
  크기에 따라 최대 1.45px 떠 있었음. 크기 10.75~22.25 × 소수 5종 × 상자 2종 80개로 새 식을 확인.
- 자간: 전역 `body` 의 −0.2px 가 물려 내려오지 않게 `.ibk { letter-spacing: 0 }`, 녹화와 −0.2 가 맞는 화면(안내·홈·이체·완료·거래내역)만 자기 CSS 에 −0.2.

- **화면 사이 로딩**: 실제 앱은 화면이 바뀔 때 파란 점 4개 원호(주기 ≈1.5초)가 폰 전체를 덮음 → `IbkLoadingLayer` + `holdIbkSpinner()`.

- **안드로이드 뒤로가기**: 이체는 한 화면이 단계(받는 분 → 금액 → 확인)로 바뀜. 단계마다 기록 칸을 쌓았다 걷었다 하면 `history.back()` 과

  '취소 → 예'는 쌓인 칸 수(`ibkBack`)만큼 한 번에 `history.go(-(n + 1))`.
- **받는 은행 오류**: 녹화 28초의 "해당기관 기타 사유로 거래가 불가능합니다 (ECBKEXT10625)". 받는 분마다 켜고 끄는 값

- **다시이체**: 상세 시트에서 `/send?bank=&number=` 로 오면 받는 분 화면은 그리지 않고 원호 아래에서 조회 → 금액 화면부터.

### 이체확인증 워터마크
이체확인증은 실제 은행 증빙 문서와 똑같이 생긴 화면이라, 클론에선 표 위에 **"연습용 화면 · 실제 이체 아님"** 을 비스듬히 반복해 옅게 깔고
'공유하기'·이체결과의 공유 버튼은 막혀 있어 눌러도 아무 일 없다 (기능 없는 다른 버튼들도 안내창 없이 무반응). 모양 비교에는 지장이 없을 만큼 옅게(표는 그대로 읽힘).

### 마지막 통합 검수에서 고친 것 (공용 · 다른 앱에도 영향)
- **아이폰 머리줄 '<' 가 절반쯤 안 눌림 (네 앱 모두)**: `ScreenStack` 이 가장자리 24px 안에서 누르자마자 `setPointerCapture` 해서 그 누름의 click 이 사라졌음
  → 누를 땐 자리만 적고, **가로로 8px 넘게 움직였을 때** 잡고 끌기 시작 (세로로 먼저 움직이면 스와이프 아님). 안쪽 부품(홈 계좌 카드)이 먼저 잡았으면 빼앗지 않음.
- **아이폰 끌기 뒤 화면이 밀린 채 멈춤**: 화면 안 뒤로가기 칸(`ibkBack`: 시트·안내창·이체 금액 단계)이 쌓인 채 끝까지 끌면 `navigate(-1)` 이 그 칸만 빼고 주소는 그대로라
  layout effect 가 돌지 않았음 → 칸이 있으면 끌기를 시작하지 않음(실제 iOS 도 시트가 떠 있으면 못 끔), 그래도 주소가 안 바뀐 뒤로면 300ms 뒤 제자리로.
- **상태바 아래 검정 1px**: 이음새를 덮는 `box-shadow: 0 1px 0 ${bg}` 에 그라데이션을 넣으면 값이 무시됨 → 그라데이션이면 마지막 색을 씀 (`seamColor`).
  그래서 전체메뉴 상태바를 녹화대로 그라데이션 (221,235,253)→(225,237,250) 으로 (PNG 로 뽑은 프레임 125장 평균. JPEG 로 뽑으면 R·G 가 +2~3 밝게 치우침).
- **전환이 끝까지 안 그려짐**: 정리 타이머가 첫 프레임보다 먼저 시작해서 100ms 메뉴 밀기가 0~67ms 에서 잘렸음 → `animationend` 에서 걷음 (타이머는 대비용).
  메뉴 닫기 130 → 100ms, 본문 왼쪽 230 → 200ms (빠진 프레임 때문에 길어 보였던 것).
- **안내창이 뜬 채 뒤로(3버튼 '<')** 를 누르면 화면이 뒤로 갔음 → 모든 화면에서 안내창부터 닫힘 (`useIbkBackHandler(!!notice, …)`).
- **홈에서 뒤로 하면 홈이 또 뜸**: 메뉴 ✕ · 완료 '확인' 이 지금 칸만 홈으로 바꿔(replace) 기록이 [홈, 홈] 이었음 → 기록 첫 칸까지 걷고(`ibkToFirst`) 홈으로.
- **시간차 경쟁**: 이동을 기다리는 동안(로딩 점 430ms, 메뉴 항목 ≈370ms, 머리줄 ← 500ms) 안내창을 띄우거나 뒤로를 누르면 기록에 칸이 남거나 뒤로 간 화면 위에
  새 화면이 열렸음 → 기다리는 동안엔 안내를 막고, 기다린 뒤 기록 칸(`history.state.key`)이 바뀌었으면 가지 않음.
- 하나원큐 `.hs-body` 에 `overflow-x: hidden` (y 만 auto 면 x 도 auto 가 되어 아이폰 터치 가장자리 끌기가 pointercancel 로 끊겼음).

자료는 실제 앱 녹화 두 개(590 × 1280, 가변 fps, 라이트, 갤럭시 제스처 내비게이션 — 첫 녹화 89초, 두 번째 녹화 101.8초). 화면마다 녹화와 겹쳐 보며 맞추고,
따로 검수(겹쳐 보기 · 흐름 · 코드) → 수리를 한 번 더 돌렸다. 값마다 근거(원본 시각 · 30fps 프레임 · px)는 CSS 주석에.
두 번째 녹화에서 새로 나온 것은 이 절 끝 '두 번째 녹화' 에.

### 좌표 · 폰 틀
- 590px = 384dp → **1dp = 1.53646px** (`theme.ts` 의 `kb()`, `kbY()` 는 환산식을 적어 둔 것). i-ONE Bank 와 달리 가로로 늘어난 것 없음.
- 폰 틀 384 × 833.08. 상태바 33.2(흰색, Roboto: SKT · 굵은 시각 · ⊖ · 5G · 신호 · 숫자가 든 배터리 알약), 아래 제스처 손잡이는
  검은 띠 없이 앱 위에 겹쳐 그림 (`.phone__gesture`). 상태바 Roboto 는 `kbank/fonts.css` 가 직접 불러옴.
- 겹쳐 보기는 **창 폭 768 + 폰 margin-top 0** 으로 폰 원점을 기기 화소에 맞춰 찍어야 함 (900 폭 창은 폰 왼쪽이 396.4px 이라 글자가 0.6~1.1dp 어긋나 보였음).

### 글꼴 (FONT.md)
- 녹화 글자 82곳(한글 53 · 숫자 29)을 후보 11종으로 그려 크기·위치·굵기를 맞춘 뒤 잉크 오차 비교 → **Pretendard 그대로**
  (한글 10.3% · 다음 Wanted Sans 11.9 · Noto 19.2, 가로세로비 1.000, 맞춘 크기가 정수 dp, 굵기는 400 / 500 / 700 세 무리).
  1차 홈의 "녹화 한글이 10% 넓다 → scaleX" 는 글자 크기를 작게 잡은 탓이었음 → 늘림·음수 자간을 모두 빼고 표의 크기로.
- 숫자 6·9 만 곧은 모양 = Pretendard **`ss01`** (숫자판 6·9 오차 62% → 8.6%). `.kb { font-feature-settings: "ss01" }`. ss01 이라 계좌번호 자간은 0.
- 굵은 금액 줄은 '1' 의 좌우가 넓고 '0' 이 조금 좁음 → `KbankDigits`(common.tsx)가 그 글자만 감싸고 화면별 값(홈 '1' 0.095em · 계좌 '1' 0.054em ·
  '0' −0.025em · 금액 입력 '1' 0.06em)은 각 CSS 의 `-n1` · `-n0`.
- 글자는 `line-height: 1`(머리줄 등 몇 곳은 px) + FONT.md 표의 left·top 에서 시작해 겹쳐 보고 다듬음. 크롬은 기준선을 CSS 1px 단위로 놓아서
  top 으로는 ±0.5dp 가 한계 — 더 맞춰야 하는 곳(홈 바로가기 이름)은 `transform: translateY()` 로 소수만큼 옮김 (기준선 맞춤 뒤라 그대로 적용).

### kbank2 — 녹화 인트로
- 같은 빌드를 `APP=kbank2` 로 띄우면 서버가 `window.__BANK_INTRO__` 를 넣어 주고, 데이터(`data-kbank2/`)·로그인 쿠키(`bank_sid_kbank2`)는 따로.
- 영상은 녹화 3.03~5.60초(30fps 프레임 92~168, 기기 홈 화면 → 금융 폴더 → K 탭). mp4(H.264, B프레임 없이 — 있으면 첫 장면이 0.233초에서 시작)와
  같은 장면 webm(VP9) — `canPlayType` 으로 고르고 못 틀면 다음 형식.
- 영상을 미리 받아 첫 장면으로 녹화 시작, 마지막 장면이 나올 때 시작화면을 밑에 띄워 1/30초 뒤 걷음. 영상 끝 장면이 시작화면 'Kbank'로
  넘어가는 중이라 같은 자리에서 이어진다.
- 크롬 화면 캡처가 긴 영상이 끝난 뒤 0.4초 멈추는 것을 막으려고 인트로 녹화 동안 거의 투명한 막의 투명도를 매 프레임 바꿈 (`keepCapturing`).
- 영상 직후 상태바가 흰 글자에서 165ms 동안 진해지고(손잡이 410ms), 캠코더는 0.986초 주기(영상이 끝날 때 켜진 지 0.37초째 → 그 위상으로
  이어 받음, `intro.ts syncBlink` — 영상 첫 장면 때도 같은 위상으로 맞춤). 영상 속 시계·빨간 알약·캠코더(`delogo=x=57:y=11:w=135:h=34`)와 배터리(`delogo=x=531:y=13:w=46:h=29`)는
  지워 두고, 영상이 덮는 동안 우리 상태바를 영상 위로 올려(`[data-intro-play]`) 그것만 영상 색(글자 흰색, 배터리 채움 흰색 · 빈 칸 흰색 34% · 숫자 #494949)으로
  그림 → 녹화에 지금 시각과 정해 둔 배터리 값이 찍힘.
- 빨간 녹화 알약 + 캠코더 표시는 인트로를 켠 kbank2 갤럭시 모드만 (끄면 kbank 와 같은 상태바). 아이폰 모드에서는 인트로 없음.
- 인트로 영상 파일은 빌드 하나가 모든 앱을 주므로 dist 에 늘 들어 있지만, 받는 건 kbank2 녹화 때뿐 (정적 import 는 주소만 넣음).

## 25. kakao2 — 카카오뱅크 새 녹화(아이폰) + 녹화 인트로 (`src/kakao2/`, `scripts/kakao-intro-erase.py`)

같은 카카오뱅크를 새로 찍은 아이폰 녹화(1180 × 2556, 60fps, 기기는 라이트 모드 · 홈만 앱이 어둡게 그림)로 다시 만든 변형. 붙이는 자리는 kbank2 · ibk2 와 같지만(23장)
그 둘은 **같은 화면 + 인트로**이고 kakao2 는 **새 화면 묶음 + 인트로**라, 원래 카카오뱅크(9101)와 다른 앱이 한 픽셀도 안 바뀌게 하는 게 가장 큰 일이었다.
녹화를 담당별 명세(인프라 · 인트로 · 홈 · 이체 · 통장 · 거래상세 · 기기)로 나눠 재고, 명세끼리 어긋난 값은 따로 검수해 한 표로 정한 뒤 만들었다.

### 서버: VARIANTS 표 하나
```js
const VARIANTS = { kbank2: "kbank", ibk2: "ibk", kakao2: "kakao" };
export const INTRO = Object.hasOwn(VARIANTS, SERVER_ID);
export const APP = INTRO ? VARIANTS[SERVER_ID] : SERVER_ID;
```
- 전엔 `INTRO = SERVER_ID === "kbank2" || SERVER_ID === "ibk2"` 와 `APP` 의 삼항 사슬이 따로라 변형을 더할 때 두 곳을 같이 고쳐야 했음 → 표 한 줄.
  `in` 이 아니라 `Object.hasOwn`: `in` 은 물려받은 속성(`toString` 등)도 true.
- 이름(SERVER_ID)이 정하는 것: 데이터 `data-kakao2/` · 쿠키 `bank_sid_kakao2` · 포트 9115(`index.mjs` 표). APP 은 `kakao` 라 API · 예시 데이터는 카카오뱅크 그대로,
  HTML 에는 `__BANK_APP__ = "kakao"` + `__BANK_INTRO__ = true` (개발은 `.env.kakao2` 의 `VITE_APP=kakao` · `VITE_INTRO=1`). 서버에서 kakao2 만 다른 건 거래구분 하나(아래).

### 화면: `KAKAO2` 상수 하나, "모든 변경은 문 안에서"
- `session.ts`: `export const KAKAO2 = APP === "kakao" && HAS_INTRO;`. 인트로 스위치(`isIntroOn()`)로 나누지 않음 — 인트로를 꺼도 화면은 kakao2 여야 하니까.
  `session.ts` 는 아무것도 import 하지 않아서 `platform.ts` · `theme.ts` · `deviceStatus.ts` 가 가져다 써도 순환 import(초기화 전 접근) 걱정이 없음.
- 문은 세 가지: JS `KAKAO2` · CSS `html[data-kakao2] …` 또는 kakao2 에서만 그리는 `k2-` 클래스 · 서버 `SERVER_ID === "kakao2"`. 공용 파일(ScreenStack · PhoneFrame · recorder ·
  ProfilePicker)도 문 안에서만 고침. 빌드 하나라 모든 앱 번들에 kakao2 CSS 가 들어가므로 새 `@keyframes` 이름(34개)이 기존 것과 안 겹치는지도 확인.
- **확인 방법**: 바꾸기 전 커밋을 worktree 로 따로 꺼내 같은 시계 · 같은 데이터로 띄우고, 다른 앱 화면과 전환 중간(60 · 150 · 300ms 에서 멈춤) 프레임을 양쪽에서 찍어 비교.
  기준끼리도 생기는 차이(둥근 모서리 안티에일리어싱 · 깜빡이는 녹화 알약 · 250ms API 지연 전후)는 빼고 모든 짝에서 나는 차이만 셈. 서버는 같은 요청 46개를 전후 서버에 보내 응답 비교.
- 실제로 걸린 것: ProfilePicker 를 `DEVICE_LOCK ?? p.os ?? OS` 로 고쳤더니 **ibk2**(갤럭시 고정)도 바뀌어, 아이폰으로 저장된 프로필을 고를 때 다시 불러오기를 건너뜀.
  `DEVICE_LOCK` 은 다른 변형도 쓰는 공용 값 → `KAKAO2 ? OS : (p.os ?? OS)`. 새 변형을 위한 분기는 새 변형 이름으로.

### 기기 · 테마 잠금
- `platform.ts`: `DEVICE_LOCK = IBK2 ? "android" : KAKAO2 ? "ios" : null` → `OS` 는 늘 ios, `<html data-kakao2="on">`. 기기 스위치 · 🔔 기기 · 프로필의 기기 설정을 안 봄.
- `theme.ts`: `lightOnly` 에 `KAKAO2` (녹화 기기가 라이트 — 앱 보관함이 밝음). 홈만 `.k2-home` 이 테마와 상관없이 어두운 색을 직접 들고 있음.
  프로필에 저장된 테마도 안 봄 (안 그러면 테마가 다른 프로필을 고를 때마다 `?theme=` 로 다시 불러왔음).
- 틀 393 × 852 · 모서리 55 · 상태바 54 · 아래 안전영역 34 (`global.css html[data-kakao2]`). 글꼴은 맥에서도 Pretendard — 아이폰 글꼴 목록을 그대로 두면
  숫자 · 영문이 리눅스에선 Inter, 맥에선 SF 로 그려져 녹화에 맞춘 크기가 기계마다 달라짐.

### 라우트 표 통째로 바꾸기 (`routes.tsx`)
`App.tsx` 의 `const render = KAKAO2 ? renderKakao2Route : ROUTES[APP];` — 콕뱅크(19장)와 같은 방법이라 카카오뱅크의 `renderRoute` 는 한 줄도 안 바뀜.
녹화에 나온 화면은 새로(`K2Home` · `K2AccountScreen` · `K2Transfer` · `K2TxDetail`), 없는 화면(다른 은행 계좌 · 금액 · 완료)은 카카오뱅크 화면을 `K2Inset` 으로 감싸 재사용.
주소 목록이 같아서 딥링크 · 새로고침이 안 깨짐. 녹화에 스플래시가 없어서 프로필을 고르면 `boot` 가 바로 `ready`.

### 상태바 · 아일랜드 · 홈 인디케이터 (`StatusBar.tsx`, `chrome.css`, `K2Inset.tsx`)
- 다른 앱은 상태바가 위 띠로 자리를 차지하고 `useStatusBar(bg, fg)` 로 띠를 칠함. 녹화를 보면 홈 내용이 상태바 밑까지 스크롤되고, 로딩 막은 띠까지 어둡게 하는데
  **글자는 안 어두워짐**(흰 글자 255 그대로) → 띠는 화면이 칠하고 글자만 위에 겹쳐야 함.
- `K2StatusBar` 는 화면 위에 겹친 투명한 층(z 70, `pointer-events: none`)이고 `useStatusBar` 의 fg 만 씀. 시각 · 위치 표시 칸(달 · 파란 위치 표시 · 화살표) · 신호 · LTE · 배터리를
  **393 × 54 SVG 한 장**에 그림 (요소마다 따로 놓으면 반올림이 달라 0.5px 씩 튐). viewport 는 852 전체, kakao2 화면은 y 0 부터 그리고 54pt 띠를 스스로 칠함.
- 재사용 화면은 `K2Inset` 이 맨 위 54pt 띠를 **그 화면이 `useStatusBar` 로 정한 색**(`StatusBandContext`)으로 칠하고 화면을 그 아래에 둠. 띠가 층과 같이 움직여서
  전환 중에도 밑 화면 띠가 제 색 (전역 상태바 값을 읽으면 밑 화면 띠까지 위 화면 색이 됨). 로그인 · 프로필 고르기도 같은 틀.
- `K2Island`: 녹화 중이거나 인트로를 켜 두면 녹화 기기처럼 넓어진 아일랜드 + 1.5초 주기 빨간 점(`BLINK_MS` 1500). `K2HomeIndicator`: 켜진 직후에만 흰색으로 나타났다 사라짐.

### 켜진 시각 저장소 (`launch.ts`)
- 스플래시가 없는 대신 앱이 켜진 직후에만 도는 것이 여럿(위치 표시 → 화살표, 홈 인디케이터, AI 알약 지우고 다시 쓰기, 배너 첫 넘김, 녹화 점 위상) →
  기준 시각 하나 `launchAt` 을 모듈 변수 + `useSyncExternalStore` 로 (콕뱅크 `loading.ts` 와 같은 작은 전역 저장소). 받는 쪽은 그 값을 `key` 로 다시 그려 처음부터.
- 기준 = 인트로 영상이 끝나는 순간 **H = 0.4167초**(25장 ÷ 60fps). `LAUNCH` 표 = 녹화 시각 − 0.4167 (ms): 홈 인디케이터 283 → 733 나타남 · 1485 → 1751 사라짐,
  위치 표시 316 · 4053, 화살표 4216, 배너 첫 넘김 5391, 녹화 점 위상 1173. 명세마다 '0초' 가 달랐음(H · "앱이 다 커진 때" · 영상 끝) → 한 기준으로 옮겨 적음 (한 명세는 전부 +241ms).
- 그냥 켤 때(프로필 고름 · 새로고침): 홈이 뜨는 때 `launchReady()`. 인트로 녹화: 영상 동안 `holdLaunch()` 로 멈춰 두고 끝나는 프레임에 `setLaunchAt(t)`.

### 로딩 막 하나 (`dim.ts`) · 모달과 push (`nav.ts`, `nav.css`)
- 홈 '이체' → 이체, 통장 거래 → 거래상세는 **누른 화면이 막을 켜고 다음 화면이 끔** → 화면 상태로는 넘겨줄 수 없어 전역 하나:
  `showK2Dim()` 그 프레임에 바로(터치 막음) · `leaveK2Dim()` 167ms `cubic-bezier(.42,0,.58,1)` 로 스피너와 함께 흐려짐(데이터를 그린 프레임에) · `cutK2Dim()` 바로 걷음.
  `rgba(0,0,0,.34)` 로 띠까지 852pt 를 덮고 상태바 글자 · 아일랜드는 안 덮음 (PhoneFrame 이 viewport 안에 `K2LoadingDim` 하나).
- 이체 쪽은 흐려지기가 끝까지 안 감: 프레임마다 재 보면 4단계 흐려지다 모달이 처음 움직이는 프레임에 남은 막이 한 번에 사라짐 → 흐려지기 시작 +50ms 모달, +67ms `cutK2Dim()`.
- 막을 끌 화면이 사라지는 경우: 거래를 눌러 막이 뜬 채 로그인이 풀려(401) 로그인 화면이 뜨면 막이 입력을 막은 채 남았음 → 로그인 안 된 동안엔 `K2LoadingDim` 이 스스로 걷음.
- 전환 종류는 ScreenStack 이 `KAKAO2` 일 때만 `k2AnimFor(anim, path)` 로 정함 (다른 앱은 className · 타이머 · `UNDER_DIM` 그대로):
  - **modal**(이체) · **detail**(거래상세): 아래에서 올라오는 전체 화면 500ms. 위끝을 프레임마다 재 보니 임계 감쇠 스프링(ω 18)이라 `cubic-bezier` 로는 안 맞음 →
    CSS `linear()` 에 21개 점: `linear(0, .075, .228, .391, .537, …, .998, 1)`. 거래상세는 막이 뜬 프레임보다 24ms 앞서 시작한 꼴(`animation-delay: -24ms`).
    밑 화면은 움직이지도 어두워지지도 않고 층도 걷지 않음(`layer--k2-under` → 닫으면 스크롤 · 불러온 목록 그대로). 가장자리 스와이프는 막음. 걷기는 `animationend`.
  - **push**(홈 → 통장): 400ms `cubic-bezier(.2,1,.45,1)`. 머리줄은 첫 프레임부터 제자리, 본문(`.k2-push-body`)만 밂. 본문 아래 두 모서리가 55로 둥글다가
    밀기가 끝나고 77ms 뒤(477ms, `K2_NAV.pushHold`) 각짐 — 앱 창이 커질 때 모서리가 늦게 각지는 것과 같은 모양. 밑 화면은 10% 어두워짐.
- 빠른 두 번 누르기는 `useK2Once`(첫 누름 뒤 이 층이 덮일 때까지 잠금, 이동이 없으면 1.5초), 주소로 바로 연 통장 · 이체의 `<` · X 는 `useK2Back` 이 홈으로
  (기록 첫 칸에서 `navigate(-1)` 하면 앱 밖으로 나갔음).

### 녹화와 맞추기
- 녹화 1180px = 393pt → **1pt = 3.0025px**. 프레임은 ffmpeg 로 60fps 그대로 PNG 로 뽑아(프레임 번호 = 시각 × 60) 위치 · 색을 재고, 움직임은 한 점(위끝 · 색)을 프레임마다 재서 곡선을 맞춤.
- 클론은 Playwright 로 DPR 3(`deviceScaleFactor: 3`)으로 찍어 녹화와 같은 화소 크기로 → 반반 붙이기 · 겹치기 · 차이 그림. 녹화의 이름 · 번호 · 잔액이 보이는 프레임은 비교에만 쓰고 커밋 안 함.
- 비교에서 고친 예:
  - **홈 스크롤 막대**: 검수는 오른쪽 x 387–390 열의 프레임별 **최댓값**이 바탕과 같다(32 vs 31)며 "홈엔 막대 없음"으로 정했는데, 막대는 바탕(31)보다 **어두운**(22) 검정 .29 라
    최댓값엔 안 잡혔음. 반반 비교에서 보여서 되살림(`k2-home__ind`) — 어두운 바탕 위 어두운 것은 최솟값으로도 볼 것.
  - **떠 있는 광고**: 명세는 '올라왔다 내려가는 시간 애니메이션'이었는데, 프레임마다 재 보니 **광고 위끝 + 스크롤 = 1162.5** 로 늘 같음 → 목록 끝에 붙어 스크롤과 같이 움직이는 것
    (맨 끝에선 제자리 667). 시간으로 흉내 내면 스크롤 속도가 다를 때마다 어긋남. 자리는 스크롤 프레임마다 ref 로 바로 (10장).
  - **거래구분 이름**: 녹화의 거래상세는 보낸 이체 '일반이체' · 받은 돈 '일반입금'. 서버 `txDetailJson` 이 `SERVER_ID === "kakao2"` 일 때만 이렇게 줌 —
    명세는 `APP === "kakao" && INTRO` 였지만 카카오 변형이 또 생겨도 안 걸리게 서버 이름으로. 🔔 패널은 보이던 거래구분을 그대로 다시 보내므로 기본값과 같은 이름은 '직접 지정'으로 안 봄.

### 녹화 인트로 클립과 개인정보 (`scripts/kakao-intro-erase.py`, `recorder.ts`, `Launch.tsx`)
- 원본은 0.458초부터 커지는 앱 창 속에 **녹화한 사람의 실제 계좌 이름 · 잔액**이 보임 → 클립은 0.000~0.400초 **25장(앱 보관함에서 B 아이콘을 눌렀다 뗌)만**,
  스크립트도 `ffmpeg -frames:v 25` 로 25장만 읽음. 그 뒤 '앱 창이 아이콘 자리에서 화면 전체로 커지는' 0.35초는 클론이 그림(`Launch.tsx`): 녹화 프레임마다 잰
  창 위치 · 모서리 · 밝기 표를 Web Animations(`el.animate`)로, 뒤에는 멈춘 영상 마지막 장면을 흐리게 · 어둡게, 416ms 에 모서리가 각지고 영상을 걷음.
- 지우기: 시계 + 달 · 배터리 칸을 줄마다 칸 바깥 왼쪽 · 오른쪽 세 칸 평균을 직선으로 이어 메움 (한 칸만 쓰면 압축 잡음이 가로 줄무늬로 남음). 영상이 도는 동안엔
  우리 상태바를 그 위에 올려(`[data-intro-play]`) 녹화한 시각 · 정해 둔 배터리가 찍힘 (kbank2 와 같은 방법). 신호 · LTE · 아일랜드는 앱과 같아서 그대로.
- 인코딩: 2배(786 × 1704)로 줄이고 RGB → bt709 tv 범위 yuv420p 를 numpy 로 직접 계산해 넘김 (ffmpeg 에 RGB 를 주면 회색이 1~2, 노란 B 가 3~10 단계 어긋났음).
  mp4 = H.264 High 4.2 · `-bf 0`(B 프레임이 있으면 편집 목록 때문에 브라우저 시작 시각이 밀림) · `+faststart`, webm = VP9. 다시 돌리면 mp4 는 바이트까지 같음.
- 녹화(`recorder.ts`): 은행마다 `IntroCfg`. kbank2 는 영상 뒤 시작화면을 새로 띄우지만(`mount: "start"`), kakao2 는 `"resume"` — 녹화를 시작하기 **전에** 영상 밑에서 홈을
  데이터 · 글꼴(`document.fonts.ready`) · 그림(`img.decode()`)까지 다 그려 둠(`resumeUnder`). 끝나기 6장 전에 `requestVideoFrameCallback` 의 장면 시각으로 H 를 계산해
  켜짐 연출을 걸어 둠 — H 에 바로 하면 무거워서 마지막 장면이 3~4장 더 찍혔음.
- 폰 폭 393 이 홀수라 짝수 폭 창 가운데에 두면 왼끝이 0.5px 에 걸려, 크롬 탭 캡처가 프레임 폭을 392 ↔ 394 로 바꾸며 오류를 내고 왼끝에 검은 1px 줄이 생김 →
  kakao2 녹화 동안만 폰 여백을 정수 px 로 옮김(`snapToDevicePixels` — transform 을 주면 Element Capture 가 프레임을 안 내보냈음).
- 저장소에 개인정보 없음: 커밋한 그림 14개(`k2-*` 12개 + 클립 2개, 클립은 25장 모두)를 열어 보고, 추가된 모든 줄과 커밋 메시지를 녹화 속 이름 · 번호 · 금액과 대조. 화면은 예시 데이터(홍길동).

## 26. allone — NH올원뱅크 녹화(아이폰) + 그린 녹화 인트로 (`src/allone/`, `scripts/allone-crops/`)

NH농협은행 앱 NH올원뱅크를 아이폰 녹화(1180 × 2556, 60fps, 라이트)로 새로 만든 앱. 기기는 kakao2 와 같은 아이폰이지만 세 가지가 달랐다:
(1) 변형이 아니라 **자기 서버를 가진 새 앱인데 처음부터 인트로가 있음**, (2) 화면이 **네이티브 껍데기 안의 웹뷰**, (3) 녹화 앞부분을 **영상으로 쓸 수 없음**.
녹화를 담당별 명세(인프라 · 시작 · 홈 · 거래내역 · 이체)로 재고, 명세끼리 어긋난 값은 `docs/allone-spec/plan.md` 한 곳에서 녹화를 다시 재서 정한 뒤
기반 → 영역 넷(동시에, 서로 import 안 함) → 통합 순서로 만들었다. 기반이 실제로 만든 내보내기 · API 는 `docs/allone-spec/foundation.md`.

### 서버: `INTRO_APPS` 와 APP / INTRO 떼기
```js
const VARIANTS = { kbank2: "kbank", ibk2: "ibk", kakao2: "kakao" };
const INTRO_APPS = ["allone"];
const VARIANT = Object.hasOwn(VARIANTS, SERVER_ID);
export const APP = VARIANT ? VARIANTS[SERVER_ID] : SERVER_ID;
export const INTRO = VARIANT || INTRO_APPS.includes(APP);
```
- 25장의 표는 `INTRO = 변형인가` 였고 APP 도 그걸로 정해졌음. allone 은 변형이 아니라 자기 앱(APP = SERVER_ID = `allone`)인데 인트로가 있음 → 두 값을 따로 계산.
  kbank2 · ibk2 · kakao2 는 결과가 그대로. 화면 쪽은 고칠 것 없음: `HAS_INTRO` 는 원래대로 `__BANK_INTRO__`(배포) / `.env.allone` 의 `VITE_INTRO=1`(개발),
  `KAKAO2` · `IBK2` 는 APP 도 보므로 false 그대로. `session.ts` 에 `ALLONE = APP === "allone"` 하나.
- 이름(SERVER_ID)이 정하는 것: 데이터 `data-allone/` · 쿠키 `bank_sid_allone` · 포트 9119 · 제목 '올원뱅크 클론 연습'.
- 올원 칸은 모두 `ALLONE` 문 안에서 덧붙임: `migrate()` 가 allone DB 에만 `accounts.blocked` · `profile.notice_on` · `profile.notice_items` · `recent_hidden` 표를 만들고,
  응답에 `blocked`(지급정지), 홈 `ao.notice`, 거래 상세 `ao: {accountId, payee}`(☆ 상태), `POST /api/payees` 의 `favorite`, 받는 분 '최근' 숨김(`HAVING MAX(t.at) > hidden_at`),
  allone 서버에만 있는 `DELETE /api/transfer/recent`(다른 앱은 404). 거래내역 기간 · 입출금 · 순서 · 20건씩은 화면이 거름 (목록 API 가 500건까지 줌).
- **지급정지를 `badge` 가 아니라 따로 칸으로**: `migrate()` 가 DB 를 열 때마다 `UPDATE accounts SET badge = NULL WHERE kind = 'main'` 을 돌려서 대표계좌 badge 는 남지 않음.
  공용 줄을 고치지 않고 allone 칸 `accounts.blocked` 를 새로 둠. 예전 '한도제한' 칸(`limited`) · 지어낸 이의제기 칸(`dispute_at`)은 `ALTER TABLE … DROP COLUMN` 으로 지움
  (node:sqlite 가 DROP COLUMN 을 지원 — 이미 쓰던 data-allone DB 도 열 때 정리됨).
- 예시 데이터는 `server/allone-seed.mjs` (`db.mjs` 가 이 파일을 import 하므로 이 파일은 `db.mjs` 를 부르지 않음). `SEEDS.allone = { example, empty }` 가 빠지면 첫 실행 · 새 프로필 · 되돌리기에서 서버가 죽음.

### 앱 id `allone` ≠ 은행 코드 `nh`
- NH농협은행 계좌의 은행 코드는 `nh` 인데 `nh` 는 콕뱅크의 앱 id 이기도 함. allone 서버의 `db().app` 은 `"allone"` 이라 콕뱅크 규칙(1일 송금 한도 · `dailyRemaining`)은 하나도 안 켜짐.
  올원 코드는 늘 `bank.code === "nh"` 로 보고, **`APP === "nh"` 로 allone 을 가리지 않음**.
- '앱 이름 = 은행 코드' 에 기대던 곳이 깨짐: `POST /api/accounts` 의 기본 은행 `bankCode = APP` → allone 이면 400 '은행을 골라 주세요' → `APP === "allone" ? "nh" : APP`.
  🔔 `OWN_BANK.allone = { code: "nh", name: "NH농협은행", … }`. AddPayee 기본 은행 사슬은 마지막 `"nh"` 로 떨어져 우연히 맞아서 그대로 둠 (`"allone"` 을 넣으면 없는 은행 코드를 찾음).
- 이름 충돌: 그림은 `allone-`, CSS 는 `ao-`(영역은 `ao-ln-` · `ao-home-` · `ao-acct-` · `ao-send-`), 키프레임도 `ao-`. 콕뱅크가 `nh-*` 그림 141개를 갖고 있어 `nh-` 는 안 씀.
  `data-kakao2` 도 안 켬 (kakao2 전환 · 인트로 CSS 가 걸림) — 틀은 `html[data-app="allone"]`.
- `AppName` 에 `"allone"` 을 넣으면 tsc 가 잡는 곳은 세 군데뿐 (`ROUTES[APP]`, overlay 표, `APP_NAME`). 나머지(시작화면 사슬 · 기기 · 테마 잠금 · 인트로 기기 · 깜빡임 주기 ·
  배터리 기본값 · 녹화 픽셀 맞춤 · 서버 SEEDS · 제목 · 포트 · 삭제 문구 …)는 **조용히 카카오 · 콕뱅크 · 보통 아이폰 쪽으로 떨어짐** → `APP ===` · `[APP]` · `KAKAO2 ||` 를 grep 해서 하나씩 (infra.md §3 표).

### 웹뷰 + 네이티브 껍데기: 흰 띠 59 / 34
- 녹화를 재 보면 웹 로딩 막 · 웹 시트 배경막이 떠도 위 0–59 · 아래 818–852 는 흰색(255) 그대로 (막은 그 사이만 덮음) → 진짜 앱은 **네이티브 껍데기 안의 웹뷰**.
  화면마다 54pt 띠를 스스로 칠하는 kakao2(25장)와 다른 모델.
- 그래서 `.phone__viewport` 를 `inset: 59px 0 34px`(`--ao-top` / `--ao-bottom`)로 줄이고 PhoneFrame 이 흰 띠 둘(`.ao-band--top/--bottom`)을 그림. 모든 화면은 759pt 웹뷰 안에서
  배치 (웹 y = 화면 y − 59). 로그인 · 프로필 고르기도 감쌀 필요가 없음 (K2Inset 안 씀). 폰(≤ 500px)에선 띠 = `env(safe-area-inset-*)`, 가짜 상태바 · 아일랜드는 다른 앱처럼 숨김.
  화면이 393pt 좌표로 그려져 있으므로 폰에선 ibk2 처럼 `.phone` 을 393 폭 그대로 두고 `zoom` 으로 창 폭에 맞춤 (`--ao-fit` = 기기 폭 / 393, 높이 = 창 높이 / 배율).
  기기 폭은 `visualViewport.width × scale` — 393 폭 폰이 잠깐이라도 창보다 넓으면 모바일 크롬이 레이아웃 뷰포트를 393 으로 넓혀 `innerWidth` 가 393 이 됨.
- 홈 인디케이터는 앱 안에선 없음. 켜진 직후(D+250 → D+1100)에만 흰 시작화면 위에 검정으로 (`AO_HOME_INDICATOR` 투명도 표).
- 검은 화면(녹화 "off" · 로그인 확인 중)을 웹뷰 안에 그리면 띠가 흰색으로 남음 → `AlloneOff` 는 네이티브 층에 창 전체 검정.

### 막 두 가지: 웹 막 · 네이티브 막
- **웹 로딩 막** `rgba(55,55,55,.68)` + 초록 all one 동전 스피너: 웹뷰(59–818)만 덮고 한 프레임에 켜지고 꺼짐. 스피너는 33ms 먼저 꺼지고, 웹뷰가 아니라 **화면** 가운데 (196.5, 425.8).
  거래 상세 · 잔액채우기 링크는 그 위에 검정 .22 한 겹이 280 / 300ms ease-out 으로 더 깔림. 웹 시트 배경막 .30(300ms ease)도 웹뷰만.
- 막 색은 흰 바탕 하나로는 못 정함: 명세 셋이 검정 .53 · (55,55,55,.68) · (56,56,59,.70) 으로 갈렸는데, 흰색(255 → 118)과 간편비밀번호 초록(#0C8F2D → (45,80,55))을
  같이 맞추면 회색 .68 만 맞음 (검정 .53 이면 흰색은 맞아도 초록이 (6,67,21)). **바탕 두 가지에서 재야 막의 색과 투명도가 같이 풀린다.**
- **네이티브 막**: 금액 입력(T7) 검정 .765 · 계좌 비밀번호(T3) .733 은 상태바 띠까지 창 전체를 덮지만 아일랜드 · 빨간 점 · 상태바 글자는 안 덮음.
- 얼마를 보낼까요(T2)의 금액 키패드 판도 네이티브라 웹 로딩 막에 덮이지 않음 (z 53 > 51). 그래서 판은 막이 켜지는 프레임에 직접 내려 보내고(170ms) 돌아오면 다시 올림.

### 상태바 글자색 덮어쓰기 (`statusFg.ts`, `StatusBar.tsx`)
- 앱 안에선 늘 흰 띠 위 검정. 바꾸는 건 **막을 연 쪽**: T7 은 아이콘(신호 · LTE · 배터리)이 600ms 뒤 한 프레임에 흰색, 시계는 667ms 뒤 100ms 동안(닫으면 한 프레임에 검정).
  T3 는 같은 네이티브 막인데 검정 그대로 → 막에 묶지 않고 `setAoStatusFg(fg, { iconsDelay, iconsMs, clockDelay, clockMs, easing })` 를 시트가 따로 부름. 인트로는 장면 동안 흰색, D+100 부터 217ms 곡선으로 검정.
- 지연은 **부른 시각부터** 잼: `setAoStatusFg` 가 `performance.now()` 를 같이 저장하고, `AlloneStatusBar` 는 같은 커밋에 클래스를 바꾼 뒤 옛 색을 Web Animations(`startTime` = 부른 시각)로 붙잡음.
  처음엔 CSS transition 이라 React 가 그리는 시간 · 프레임 위상만큼 밀렸음.
- `null` + 타이밍이면 500ms 안에 오는 화면 fg 바뀜에도 같은 타이밍 (시작화면의 `useStatusBar("dark")` 가 한 프레임 뒤에 와서 글자가 검정으로 튀었음).
- 상태바는 K2StatusBar 를 옮겨 와 맞춘 393 × 54 SVG 한 장: 시계 잉크 가운데 x 60.0(옆 표시 없음), 신호 막대 4칸(kakao2 와 같은 모양), LTE · 배터리 · 숫자는 kakao2 보다 1.0~1.33pt 오른쪽,
  배터리 빈 칸 .333 · 기본 50. 아일랜드 · 빨간 점(1.5초 주기)은 같은 기기라 `K2Island` 를 그대로 import.

### 인트로를 그린 이유 (`launch/Scene.tsx`, `launch/intro.ts`, `intro.ts`, `recorder.ts`)
- kakao2 는 앱 보관함 25장을 쓸 수 있었지만, 올원 녹화 0–1.15초의 홈 화면엔 녹화한 사람의 배경화면 · 설치한 앱 · 알림 숫자가 그대로 보임 → **그 구간 프레임은 한 장도 안 씀**.
  아이콘 누름 · 녹아 사라짐도 그 배경 위라 영상으로 쓸 수 있는 구간이 없음.
- 대신 DOM/SVG 장면: 자리 · 크기만 녹화에서 잼 (1열 아이콘 64pt, 왼끝 28.7 / 119.6 / 210.5 / 301.4 · 위끝 80, 검색 알약, 독 둥글기 40). 배경은 만든 그라데이션,
  아이콘은 '금융' 폴더(로고 없는 파스텔 칸) · 메모장 · 날씨 · 이름 없는 독 4개 · all one 아이콘(CSS 초타원 + 워드마크 마스크). 그림 파일은 `allone-wordmark.png` 하나 (다른 래스터를 읽지 않는 것이 검사 항목 — plan.md §7.1).
- **줌이 아니라 녹아 사라짐**: 인프라 명세는 '아이콘 자리에서 흰 창이 커짐' 이었는데, 화면을 6 × 4 칸으로 나눠 칸마다 흰색 비율을 재 보니 모든 칸이 같이 올라감
  (.04 → .2 → .5 → .85, 50ms 간격) → 화면 전체 250ms 균일 페이드, 곡선은 `linear()` 16점.
- 시각표 (녹화 첫 프레임 t0 기준, C1 그대로): +650 아이콘 누름(한 프레임에 바탕 #0C8F2D → #034913, 글자 흰색 → #919291, 크기 그대로) · +900 = **D** 손 뗌 —
  아이콘 100ms ease-out 복귀 + 장면 위 흰 막 250ms · D 에 `aoSetLaunchAt(D)` + RESTART "start"(그 밑에 시작화면이 흰색으로 이미 그려짐) · D+100 상태바 글자 → 검정 217ms · D+300 장면을 걷음.
  누름 · 녹아 사라짐은 미리 걸어 둔 Web Animations(`startTime = t0`)라 그 프레임에 DOM 바뀜이 없음.
- 녹화기 갈래(영상 `IntroCfg` 갈래는 그대로): `prepareAlloneIntro()`(글꼴 · 워드마크, 늦어도 3초) → RESTART "off" → `showAlloneIntro()`(장면이 폰을 덮음 — 첫 프레임이 검정이 아님)
  → 녹화 시작 → 첫 프레임 뒤 한 프레임 → `keepCapturing`(가만있는 장면도 매 프레임 찍히게, 23장) · `syncBlink(618)`(빨간 점이 녹화 0.62초에 가장 어둡게) → `runAlloneIntro`.
- 멈췄다가 0.9초 안에 다시 ● 녹화하면 지난 녹화의 "start" 가 새 장면 밑에 갔음 → 세대 번호로 밀려난 실행은 아무것도 안 켬.
- 폰 폭 393 이 홀수라 kakao2 의 `snapToDevicePixels` 를 allone 에도 (25장). 단 DPR 3 에서 크롬이 자리를 1/64px 단위로 저장해(63.6667 → 63.65625) 0.01 검사에 걸려 되돌려졌음

### 잔액채우기 = 이체 (`transfer/Topup.tsx`, `api.ts topup`)
- 새 API 없이 `POST /api/transfers`: 내 다른 계좌(KB · 케이뱅크 …) → 받는 NH 계좌, `memoTo = memoMe = "잔액채우기"`. 서버가 이미 출금 거래 + (내 계좌면) 입금 거래 + 이체 기록을
  `transaction()` 하나로 묶으므로(14장) 양쪽 통장에 '잔액채우기' 행이 생김. 내 계좌로 보낸 것이라 '최근' 목록에는 끼지 않음.
- 1회 한도 500만 · 1일 잔여한도(100만 − 오늘 그 계좌에서 채운 합계, `GET /api/transfers?from=` 의 오늘 기록 중 잔액채우기)는 표시 + 화면 검사만. 서버 한도는 없음 → 검사를 지나면 늘 성공.

### 화면 전환: push · pop · cut · fade · reveal · load (`nav.ts`, `nav.css`, ScreenStack 토스 갈래)
- 명세마다 push 가 달랐음 (+33dp / 270ms, +160dp / 450ms, 380ms, '60–80ms 교차' …). 세 번의 push(A 14.134 · A 45.406 · B 9.960)를 같이 맞추니 **곡선 하나**:
  새 층 +150dp → 0, 400ms `cubic-bezier(.05,.7,.1,1)`, 처음 50ms 에 나타남 (RMS 1.7dp). 다른 값들은 같은 움직임을 늦은 첫 프레임에서 잰 것 · 옛 화면이 흐려지는 시간을 잰 것이었음.
- 옛 층: 내용은 60ms 직선으로 흐려지며 −12dp, 띠와 바탕은 95ms 남았다 사라짐 → 그 사이 새 층 위 빈자리가 폰 바탕(검정) = 녹화의 검은 상태바.
- pop: 닫히는 층 0 → +40dp 120ms `(.4,0,1,1)`, 흐려지지 않음. 드러나는 층은 바탕 · 띠만 보이다가 닫힘이 끝나면 내용이 −5dp → 0, 120ms (B 54.39–54.66).
- cut(탭 사이 · 증명서 단계 · 금액 → 확인 → 보내는 중/완료) · fade(쿠폰 광고 닫기 90ms) · reveal(완료가 pop 처럼 내려가고 밑에 처음부터 있는 쿠폰 화면의 내용이 150ms 뒤 300ms 에 나타남, replace 로 감) ·
  load(push 인데 옛 층 내용을 처음부터 숨김 — LOAD 빈 화면 밑 화면이 번쩍이지 않게).
- 고르기 `tossAnimFor(navType, to, from)`: `state.tossAnim` → 길 규칙(cut) → push / pop, 나가는 화면 state 에 `tossExit: "fade"` 면 fade. 걷기는 그 전환의 마지막 애니메이션 이름으로(`TOSS_ANIM_END`) —
  안쪽 요소의 `animationend` 도 올라오므로 이름으로 가림 (타이머는 대비만).
- `useTossGo()` (kbank `useKbankGo` 를 옮김): 맨 위가 아닌 층에서 온 이동은 버림, 이동 뒤 450ms 잠금, **손 뗀 뒤 120ms 에 이동**(녹화의 웹뷰 기다림 0.46–1.7초를 줄임, 그 사이 누름 표시가 170ms 에 사라짐),
  그 사이 뒤로 갔으면(지금 칸이 바뀜) 안 감.
- 깊이: `location.state` 의 `sendDepth` · `certDepth` 를 push 마다 +1 (replace 는 그대로, `carryDepth`) → 흐름 나가기는 `history.go(-depth)` (`useTossExit`, 기록이 모자라면 fallback 으로 replace).
- 화면 안 뒤로 `useTossBackStep`: 시트 · 안내창 · 자판이 떠 있는 동안 방문 기록 한 칸(`tossBack` 깊이)을 쌓아 두고 뒤로가기로 빠지면 닫기 (kbank `sendback.ts` 꼴, 겹치면 나중 것부터).
  닫자마자 다른 칸을 쌓거나 replace 하면 순서가 꼬여서 그 칸이 빠지는 popstate 를 기다린 뒤에 함 (`transfer/guard.ts nextPop`).
- 완료(S8) · 광고 화면의 지킴 칸: 갤럭시 뒤로로 칸이 이미 빠졌는데 방금 replace 로 와서 이동 잠금(450ms) 중이라 나가기를 버리면, 다음 뒤로가 끝난 이체의 금액 화면으로 감 →
  `tossAfterLock(fn)` 으로 잠금이 풀린 뒤에 나감 (`useAdBackGuard` · `useDoneGuard`). 보내는 중(S7)은 `hold()` 로 칸만 바로 다시 쌓음.
- 주소 바로 열기(새로고침 · 링크)에 보여 줄 것이 없으면 `ui/Redirect.tsx TossRedirect` 가 맨 위 층일 때 한 번 replace: 없는 주소 · 없는 탭 → 홈, 받는 분 없는 금액 · 확인 → 어디로 보낼까요
  (금액 없는 확인 → 금액), 고른 내역 없는 증명서 완료 · 문서 → 증명서 홈, 다른 은행 계좌를 `/bank/` 로 → `/account/` (반대도). 없는 계좌는 '계좌를 찾을 수 없어요'.

### 흐름 도우미 (`flow.ts`, `toast.ts`, `loading.ts`)
영역은 서로 import 하지 않고 주소와 이 함수들로만 오감:
- `goBank(id, { toast })`: '토스뱅크로 이동했어요' 토스트를 push 시작 100ms 뒤에. 통장이 잔액을 그리면 `tossToastReady()` → 최소 1.45초와 '다 그린 뒤 +100ms' 중 늦은 때 나감.
- `goSend({ from })`: 120ms 뒤 LOAD 빈 화면(#171619 + 회색 스피너, 상태바 밑) → 받는 분 목록을 미리 받음(≥ 400ms) → `/send?from=` push(`load`, `sendDepth: 1`) 와 **같은 렌더에서** LOAD 를 걷음.
- `useSendFinish()(kind)`: 광고를 안 미뤘으면 완료(S8) 자리를 replace — 옮기기 `/ad/coupon`(reveal, 닫을 땐 fade) · 보내기 `/ad/payback`(push + '토스로 이동했어요'). 미뤘으면 `history.go(-sendDepth)` 로 흐름 전 화면(pop).
- `useAdDismiss()({ snooze })`: '3일 동안 안보기' = `PATCH /api/profile { adSnoozeUntil: 지금 + 3일 }` → `history.go(-sendDepth)`. 광고는 S8 를 replace 해서 깊이가 그대로.
  광고 화면은 갤럭시 뒤로를 받으려고 기록 한 칸을 쌓아 두므로, 버튼으로 닫을 땐 그 칸을 먼저 걷고(popstate 를 기다림) 나감 — 안 그러면 `go(-sendDepth)` 가 한 칸 모자람 (`home/boot.ts useAdBackGuard`).
- `certExit()`: `history.go(-certDepth)` — 상세 · 전체 메뉴 둘 다 `certDepth: 1` 로 증명서에 들어옴.

### 홈 (`home/`)
- **시작화면 → 홈 교차**: App 은 시작화면을 걷고 나서 ScreenStack 을 그려 두 화면이 같이 있지 않음 → 시작화면이 끝난 때를 적어 두고(`markSplashDone`) 홈이 처음 그려질 때 시작화면 그림을 위에 덮었다가 300ms 에 걷음.
  1.2초 중 0.6초에 심볼이 7.2dp 내려감 (명세는 8, 녹화 A 3.75 → 6.5 가 7.2). 첫 프레임에 심볼이 없던 것 → 앱이 뜰 때(로그인 전) 그림을 미리 받아 `decode()`.
- **숫자 굴림을 녹화 시각에** (`boot.ts`): 처음엔 홈이 다시 보인 뒤에야 `/api/home` 을 받아 pop +540ms 에 굴렀음 (녹화 +110ms). 홈이 안 그려진 동안 데이터가 바뀌면(이체 · 관리 패널 — `subscribeVersion`)
  그때 홈 데이터를 미리 받아 둠 → +139ms. 마지막으로 보인 금액은 프로필 + 칸 이름으로 기억하고 처음 보는 값은 안 굴림. 맨 왼쪽 자리가 +355ms, 맨 오른쪽이 +520ms 에 멈춤.
- 머리줄 회색 토스 표시: 반쪽마다 음영이 달라 그라데이션 하나로 안 맞음 → 파란 심볼의 밝기를 SVG 색 행렬로 회색에 대응 (평균 화소 차 4.6).
- 누름: 줄 바탕이 0.82 폭에서 120ms 에 넓어지고, 떼면 32ms 머물다 135ms 직선으로 사라짐, 이동은 +121ms. 리워드 배너 × 는 그 달을 `profile.reward_dismissed` 에 저장하고 흐려진 뒤 칸이 접힘 (🔔 '다시 보이기' 로 풀면 열린 홈에 다시 나타남).
- 그림 11장(`scripts/toss-crops/home.py`): 멈춘 구간 여러 장 평균 → ESRGAN 4배 → 녹화와 맞춰 보정(back-projection) → 바탕 걷기. 2,000원 광고의 달력 로티는 열쇠 장면 5장을 1.9초로 돌림.

### 녹화와 맞추기
- 녹화는 가변 프레임률이라 프레임 번호가 아니라 **시각**으로 뽑음 (`ffmpeg -ss <시각> -i 녹화 -frames:v 1`). 멈춘 화면은 여러 장(홈은 25장) 평균해 압축 잡음을 줄인 뒤 잼.

  움직임은 rAF 로 찍은 프레임과 녹화의 한 점(위끝 · 밝기)을 프레임마다 비교.

### 남은 차이 (일부러 · 못 맞춘 것)
- **글꼴**: 토스 글꼴 대신 Pretendard 하나 (기계마다 같게). 긴 글줄은 최대 3–4dp 넓고, 숫자 · 띄어쓰기가 든 글은 1–2dp, 괄호는 1.5–1.8dp 아래로 내려감. 소비 합계만 가로를 줄임.
- **로티**: 동전 · 완료 체크 · 방패 체크는 CSS / SVG 흉내 (시각 칸은 맞음, 혜성 · 불꽃 · 모양 바뀜은 줄임), 2,000원 달력은 장면 5장을 cut 으로 (녹화 한 바퀴 ≈2.1초 중 한 구간이 다시 배치와 겹쳐 1.9초 유지).
- **그림 모양**: 은행 글리프는 하나원큐 것(`hana-bank-*`)이라 토스 그림과 다른 은행이 있음, 목록 둥근 네모는 진짜 초타원이 아님, 톱니는 공용 모양, 홈 '모두 보기' 누름은 손가락 자리 물결 대신 가운데 띠.
- **줄인 기다림**: 웹뷰 기다림(통장 1.3초, LOAD ≥ 0.4초, W 2.6초, 누른 뒤 120ms), 거래내역 ✓ 800ms (녹화 B ≈ 420ms).
- **안 만든 것**: 잠금 화면, 보안 창의 검은 구간, 다른 앱 알림, 엣지 패널 손잡이, 토스뱅크에서 돌아올 때의 새로 불러오기, 소비에서 돌아올 때 배너가 다시 나타나는 것, 창 열림 확대(220ms 흉내만),
  S2 커서 자리 · 선택 손잡이, S3 끝 튕김, S4 스피너 → 뼈대 순서 · 붙여넣기 칩, 오래 누른 버튼의 물결, 증명서 홈의 웹뷰 +53.6dp 튐 · 소개의 두 번째 옅은 뼈대.

- **신용카드 데이터**: `cards.kind` check / credit + `bill`(다음 카드값) · `pay_day`(결제일). 다음 결제일 = 오늘 ≤ 결제일이면 이번 달, 지났으면 다음 달 (없는 날은 그 달 마지막 날).
  신용카드 사용 내역은 넣지 않음 — 거래는 계좌에 붙어야 해서, 넣으면 결제 계좌의 거래내역 · 거꾸로 계산하는 잔액에 섞임. 그래서 소비엔 Day 사용분이 없고,
  카드값은 홈 줄 + 결제일의 '하나카드' 자동이체(소비에서 제외)로만 보임. 예시는 오늘이 14일 전이면 이번 달 카드값, 지났으면 이번 달 자동이체 + 다음 달 카드값.
- **예전 DB**: CHECK 를 ALTER 로 못 바꿔서 `migrate()`(토스만)가 `last_used_at` 칸이 남은 예전 cards 표를 한 번 새 표로 옮김 — 예시 선불카드(`c-youth`)는 예시 신용카드 `c-day`
  (카드값 = 예전 잔액), 그 밖의 선불카드는 체크카드, 그림 이름도 새 이름으로. 계좌 이름 · 다른 카드 · 거래는 사용자 데이터라 안 건드림 → 성인 예시 전체는 🔔 → 기본 → 예시 데이터로.
- 잔액은 거래 후 잔액(지금 잔액에서 거꾸로 계산)이 석 달 내내 0원 밑으로 안 내려가게 맞춤 — 급여가 두 번 들어오므로 통장 잔액을 그만큼 넉넉히. 여러 '오늘'(1일 · 14일 · 15일 · 말일)로 넣어 봄.

### 다른 앱이 안 바뀌게
- 문은 셋: JS `TOSS` / `APP === "toss"` · CSS `html[data-app="toss"]` 또는 `toss-` 클래스 · 서버 `TOSS`. 새 코드는 `src/toss/` · `server/toss-*.mjs`, 공용 파일은 문 안의 갈래만.
- 확인은 기반 단계에서 25장 방법으로: 바꾸기 전 커밋을 worktree 로 띄워 다른 8개 서버에 같은 요청을 보내 응답을 비교하고, 배포판(각자 자기 dist)으로 홈 · push 중간(60 · 150 · 300ms) 화면을 비교.
- 한 빌드에 모든 앱 CSS 가 들어감: 다른 앱의 접두 없는 클래스(`.done { background: #fff }` 같은 것)가 토스에도 걸릴 수 있어 토스 클래스는 모두 영역 접두(`toss-home-` · `toss-acct-` · `toss-send-` · `toss-cert-` · `toss-assets-`).
  `@keyframes` 이름도 `toss-` 로. TSX 의 className 도 `toss-` 로 시작 (on · out · red · blue · open 같은 꾸밈 이름만 예외) — `.done` · `.home` · `.btn` 같은 맨 클래스는 실제로 토스 요소에 걸림.
- 일부러 빌려 쓰는 것: 이체 번호 자판은 하나원큐 `.hana-kb*` CSS 를 그대로 씀 → 토스만의 조정은 `transfer/send.css` 의 `html[data-app="toss"] .hana-kb…` 에만 (하나 규칙은 안 고침).
- 공용 프로필 시트(흰 바탕 · 노란 버튼)는 `.picker--toss` 아래에서만 토스 어둠 · 파랑, 새 프로필 안내 문구는 `TOSS ?` 갈래 (토스뱅크 통장 · 토스머니 0원).

### 배운 것
- 명세 여섯이 같은 push 를 여섯 가지로 적음 → 다른 첫 프레임 · 다른 점을 잰 것. 여러 번의 이동을 한꺼번에 맞춘 곡선 하나가 나머지를 다 설명함.
- 상태바를 '화면이 칠하는 띠 + 위에 겹친 글자' 로 나누면 push 중 검은 상태바 · 막 밑에서 밝은 시계가 흉내 없이 나옴 (kakao2 에 이어 두 번째).
- 재는 도구가 반 픽셀 어긋나면 모든 x 가 같은 쪽으로 틀림 — 비교하기 전에 폰 왼끝이 기기 픽셀 위에 오는지부터.
- 색은 평균 말고 획 최댓값, 멈춘 화면은 평균 프레임, 움직임은 한 점을 프레임마다. 시작 · 끝만 맞추면 가운데(고리 170ms, 반짝임 주기)가 틀림.
- 맨 위 층만 그리는 스택에선 '돌아온 화면 = 새 화면': 칸(key)마다 기억해 POP 일 때만 되살리고, 안 보이는 동안 바뀐 데이터는 그때 미리 받아 둬야 돌아온 순간이 녹화 시각에 맞음.
- 영역을 동시에 만들 땐 공용 파일을 얼리고 '수정 요청'으로 받아 통합에서 한 번에 — 영역끼리 안 부딪힘. 대신 영역 안 덮어쓰기는 통합 때 같이 걷어야 두 번 걸리지 않음.
- 영역을 다 만든 뒤 영역마다 녹화 대조 검토를 한 번 더: 만든 사람이 '±0.5dp' 라 적은 값이 다시 재면 1.4dp 였고, 명세 값(8dp · 2.3초 · 0.9348 · 16px)도 여럿 틀렸음.
- 배포판만의 버그: 빌드의 CSS 압축이 이름 없는 `animation: 1900ms linear infinite both` 를 `animation: none` 으로 바꿔 2,000원 광고 달력이 배포판에서만 안 보였음 →
  이름이 없을 땐 longhand(`animation-duration` …)로. 애니메이션을 끄고 찍은 화면 비교로는 못 찾고, 개발 서버와 배포판의 계산된 스타일을 견줘서 찾음.
